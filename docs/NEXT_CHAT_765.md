- 760: PID для двух реальных CPL3/EL0 контекстов в тестовом профиле — CI PASS.
- 761: загрузка службы процессов с пустым PID-реестром — CI PASS.
- 762: структурная модель SAFE и USER-A/B таблиц, W^X, без активации — CI PASS.
- 763: контролируемое T-P1.4 CR3→возврат (не корни 762) — CI PASS.
- 764: конечный ledger владения внешне подтверждёнными страницами и PID —
  база `f8d38cea0aca9b5b0cf24da275a45f1d0e5ad39d`, CI run `44919830944` PASS.
- **765:** image-owned 72+6 page physical attestation, read-only UEFI page
  walk and independent linked-PE RVA proof in real QEMU; это не PMM и не
  применение корней 762. **См. фактический CI ветки**, не считать PASS заранее.

## Следующая задача 766

Начать отдельную ветку **от принятого 765**, не удалять/не переписывать
предыдущие. Спроектировать и в отдельном QEMU-профиле проверить неполный пока

## Продуктовые ограничения

- Не менять `main` без разрешения; каждый этап имеет собственную ветку.
- Не менять рабочий стол, экранов приложений и UI-макетов без согласования;
  формат всех родных системных приложений — `.tea`.
- Не выдумывать PIDs, CPU%, RAM; не считать сеансы окон процессами.
- Хранить историю реконструкции 709/730, двухдисковую схему и Deep Drop.
- Позже: настоящие учётные записи, изоляция данных и **выбор пользователя
  строго по утверждённому макету**; визуальный выбор без изоляции не считать
  безопасным входом.
- Не считать тесты QEMU доказательством VirtualBox, физического ПК, ARM/Android.
