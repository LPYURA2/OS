# Учебная практика T1A: как ОС запускает программу

## 1. Разница между исходным и машинным кодом

`programs/hello.asm` — текст для человека. `tools/export_images.py` переводит его в машинные инструкции M32 и помещает бинарник в `images/system.img`. Python делает эту работу **при сборке**, до запуска системы. Во время включения ОС машинные байты уже находятся на диске.

## 2. Как гостевой CPU читает диск

В `kernel.asm` последовательность выглядит так:

```asm
OUT 50, R6     ; номер сектора диска
OUT 51, R14    ; адрес в RAM, куда писать 512 байт
MOVI R3, 1     ; аппаратная команда READ
OUT 52, R3     ; выполнить чтение
IN R0, 53      ; статус (1 — успешно)
```

`OUT` и `IN` относятся к устройствам, которые эмулирует Python. **Но адрес, номер сектора и решение начать чтение определяет код ядра**, исполняемый нашим процессором.

## 3. Зачем контрольная сумма

Гость считывает по 4 байта, складывает все слова блока, сравнивает получившееся число с каталогом. Если сумма отличается — выводит `APP LOAD ERROR` и останавливает загрузку. Это не цифровая подпись и не защита от злоумышленника.

## 4. Зачем фиксированный адрес

Сейчас `MOVI R0, message` превращается в абсолютный адрес в машинной инструкции. Поэтому hello, собранный для слота 0, нельзя безопасно переместить в слот 3: текст/данные окажутся не там. В будущем потребуется релокация, адресно-независимый код либо иной формат `.tea`.

## 5. Проба для самостоятельной работы

В Termux (в папке v0.3.2):

```sh
nano programs/hello.asm
```

Найди `.ascii` и измени текст сообщения, сохрани файл, затем:

```sh
python tools/export_images.py
python tools/export_images.py --check
python matryoshka.py --os
```

Внутри OS введи `run 0`. Программа выведет твой текст. **Что ты сделал:** изменил ассемблер → собрал бинарный образ → ядро загрузило его с виртуального диска → CPU исполнил.

Практика следующего уровня: найти в `kernel.asm` подпись `load_program:` и проследить, какие регистры содержат номер сектора, адрес загрузки, количество секторов и сумму.

Обрати внимание, что для исправления ошибки исходник меняется в `.asm`, а не вручную в `system.img`.
