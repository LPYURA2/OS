# StyleOS 765 — аттестация образных физических страниц (проверяемая граница)

База: **764** (`f8d38cea0aca9b5b0cf24da275a45f1d0e5ad39d`), ветка
`feature/styleos-physical-grant-attestation-765`.

## Реально добавлено

Для **отдельного x86-64 UEFI тестового образа** `--test-frame-grants`
создаются **72 страницы таблиц (3 × 24)** и **6 страниц будущих пользовательских
буферов** (2 × код/стек/данные) в его собственном выровненном PE/BSS. Модуль
`kernel/frame_grant_proof.c` проверяет, что интервалы целиком лежат в
загруженном образе, содержатся в зарезервированной памяти нормализованной
карты UEFI, не принадлежат `CANDIDATE`, не пересекают живые стек,
boot-handoff, исходную карту, рабочие метаданные и boot-pool и не
перекрываются друг с другом.

Это **только структурная политика**, она сама по себе не является
физическим доказательством. Доказательство в специальном госте дополняется
`arch_paging_attest_image_writable`: после проверки контекста и реального
возврата на исходный CR3 старый x86 read-only walker проходит **каждую из
78 страниц**, проверяя PA=VA, WB, writable и прочитанные PTE старого корня.
Он использует уже выполненные T-P1.4 проверки CPU, образа, исходных таблиц,
GDT/IDT и факта зарезервированного PE.

В CI отдельный `tools/test_frame_grant_guest.py` запускает QEMU+OVMF,
пересчитывает результаты из настоящей карты UEFI и **RVA двух объектов в
линкерном map** — не принимает красивую строку PASS без бинарного/аппаратного
доказательства, не принимает подмену UART. Исторический verifier 763
по-прежнему проверяет весь цикл `old CR3 → owned CR3 → old CR3` и
снимки таблиц. Отдельный `test_frame_grant_proof.py` (ASAN/UBSAN)
проверяет отказы: alias, невыравнивание, стек/метаданные, outside image,
недостаточное резервирование, candidate, испорченные счётчики.

## Критические ограничения

- Это **зарезервированные страницы исполняемого тестового PE**, а НЕ свободная
  общая оперативная память, отданная firmware/PMM пользовательскому процессу.
  Не было передачи прав владения, реального размещения `.tea`, удаления
  отображений родительского UEFI и изоляции секретов между пользовательскими
  задачами.
- Специальный образ 765 не активирует **никакие новые** корни
  `desktop_vm_stage` из 762. Только предыдущий T-P1.4 образный CR3
  испытывается аппаратно для уже проверенного roundtrip.
- Без PE closure по реальным секциям (W^X), IRQ/TSS/стекам, MMIO/драйверам,
  памяти диспетчера и границам жизненного цикла **нельзя** передавать эти
  PAs в production `dfo_prepare`, даже при успешной аттестации 78 страниц.
- **Нет** PMM, отсутствуют фоновые настоящие `.tea` процессы, IPC/syscall,
  реальные метрики CPU/RAM, вход пользователей. Рабочий стол, формат `.tea`,
  второй диск и `main` не менялись.
- Результат CI подтверждает QEMU/OVMF только для данного коммита, не
  VirtualBox/телефон и не физический ПК.

## Запуск

```sh
python3 tools/test_frame_grant_proof.py --output build/765/host
python3 tools/build.py --arch x86_64 --test-frame-grants --output build/765/guest
python3 tools/test_frame_grant_guest.py --output build/765/qemu
python3 tools/build.py --arch x86_64 --desktop-v0 --output build/765/desktop
```
