# StyleOS 779 — унаследованные отображения ядра, аппаратная инвентаризация

## Фактический объём

После **успешного** T-P1.4 CR3 roundtrip с возвратом к исходному корню UEFI,
`arch_paging_inventory_inherited()` заново сравнивает аппаратные CR0/CR3/CR4,
EFER, PAT, IF, GDTR/IDTR и CS с ранее принятыми значениями. Не доверяет
адресам из пользовательского контекста и не использует страницы кандидатов RAM.

Под действующим **унаследованным** CR3 архитектурный page walker для **каждой**
страницы следующих областей возвращает её физическую страницу, тип кэширования
PAT, права RW/X и бит U:

- всего диапазона реально загруженного PE-образа (`BOOT_MEMORY_IMAGE`);
- действительного boot stack из boot-memory evidence;
- страниц в аппаратных GDTR и IDTR, включая границы диапазонов;
- физических страниц **старых** таблиц, которые посетил page walker.

Учётный модуль `kernel_mapping_inventory` проверяет выравнивание, нижнюю
каноническую половину VA, допустимые PA, WB RAM и `U=0`; для образа и таблиц
дополнительно проверяет identity mapping. Одновременно считает фактические
страницы с RWX (это **дефект доверенного наследуемого отображения**, а не
разрешение строить новую карту памяти с такими правами).

UART выводит единственную строку `STYLEOS KMI 779 INHERITED ... active=0` с
реальными счётчиками и restored CR3. Независимый тест связывает число image и
stack страниц с физическими диапазонами UEFI в том же аппаратном журнале,
а CR3 — с зафиксированным успешным CR3 restore. Отказ или подмена строки
не принимаются.

## Принципиально НЕ доказано

- Полнота **новых** root tables, динамических kernel stack / IST и TSS;
- firmware runtime code/data, GOP framebuffer и MMIO; драйверы, DMA, IRQ;
- PFNs, которым выделение физической памяти действительно передало владение;
- соответствие требуемым безопасным RX/RW/NX вместо legacy RWX;
- корректность кеширования PAT/PWT/PCD/драйверных MMIO для нового CR3.

Инвентаризация не экспортирует API включения новых CR3. Факт отображения
старых страниц сам по себе **не** означает, что ими владеет StyleOS.

## Приёмка

Host ASAN/UBSAN/COFF проверяют fail-closed policy. Отдельный QEMU/OVMF профиль
проверяет аппаратную цепочку `OLD CR3 → TEST CR3 → RESTORED OLD CR3 →
KMI inventory` и отказ неполным root tables 777/778. Ни один из root tables
777/778 не используется для обычного Desktop. Существующая пользовательская
оболочка и `.tea` не изменяются.

## Дальше: 780

Получить явные физические источники для TSS/IST, стеков, GOP/MMIO и firmware
runtime, разделы PE для RX/RW/NX, аппаратные cache attributes. Построить
реестр зависимостей + policy отказа на неполной цепочке, прежде чем
планировать пробный switch к собственному безопасному root. Не пропускать
последнюю проверку архитектурной безопасности ради раннего UI.
