# StyleOS 777: аппаратно подтверждённые image-owned страницы → неактивные корни

База: 776, коммит `379e9c52569463aa763d79d35b3e5a30fdc5240a`.
Ветка: `feature/styleos-attested-detached-roots-777`.

Модуль `desktop_grant_bridge` допускает построение трёх конечных
отсоединённых таблиц x86-64 ТОЛЬКО после:
1. политики 765: 72 страницы таблиц + шесть приватных страниц внутри
   зарезервированного PE-образа; без candidate RAM и пересечений;
2. аппаратного inherited-CR3 walker x86: присутствие, WB/writable,
   физическое identity mapping для каждой страницы, после полного
   возврата к исходному корню;
3. проверки отдельной supervisor диагностической страницы;
4. конструктора 762/764: SAFE не содержит пользовательских страниц,
   A/B отображают собственные code (RX), stack/data (RW/NX).

Итого 79 проверенных страниц. Отказ архитектурного callback при любом
из восьми вызовов предотвращает подготовку корней. Проверки ASAN/UBSAN
используют модельный callback и НЕ заменяют аппаратного QEMU.
Аппаратный профиль 765 расширен проверкой именно нового модуля; UART
содержит `STYLEOS DGB PASS pages=79 roots=3 active=0 no-pmm=1`.
Верификатор требует строку и проверяет намеренную порчу маркера.

**Критическое ограничение:** SAFE содержит только одну диагностическую
страницу, а не код ядра/стек/GDT/IDT/TSS/драйверы и MMIO. Эти корни
НИКОГДА не активируются; настоящего PMM, фоновых .tea, пользователей или
общего install manager пока нет. Штатный Desktop сохраняется.

**Этап 778:** создать и доказать полный SAFE kernel mapping closure с
разрешениями W^X и корректной защитой стека/системных объектов, затем
отдельно провести аппаратный CR3 roundtrip новых корней в QEMU.
Только после этого — связывать disk .tea staging с координатором 775
и настоящим scheduler/IPC. Завершить установщик .tea (сейчас есть
host-staging девяти приложений и системное окно установки), далее вход
по утверждённому макету, StyleFS, Проводник («Быстрый доступ»).
