# Deep Drop 72 — передача текста через CPL3 и оконный IPC

Обычный x86-64 образ с собственным корнем таблиц страниц обрабатывает пять
вызовов через INT 0x80. Общий ABI находится в
[deep_drop_abi.h](../../include/styleos/deep_drop_abi.h).
Реестр процессов, поколение, фактический CR3, изолированное окно и активный
сеанс проверяются в тех же границах, что и для оконных вызовов .tea.

| Событие или операция | Параметры | Эффект |
|---|---|---|
| Захват мыши и отпускание над другим видимым окном | Источник и цель определяет композитор | Источник получает в своей ограниченной очереди REQUEST_TEXT с идентификатором жеста |
| OFFER 0x110 | RBX = жест, RCX = адрес, RDX = длина | Копирует валидный UTF-8 из приватной страницы источника. Цель получает TEXT_OFFER. В RDX возвращается идентификатор передачи |
| ACCEPT 0x111 | RBX = передача | Выбранный получатель разрешает выдачу |
| READ 0x112 | RBX = передача, RCX = адрес, RDX = вместимость | Записывает байты один раз. RDX содержит фактическую длину. После выдачи ядро затирает содержимое слота |
| FINISH 0x113 | RBX = передача | Получатель подтверждает выдачу. Ядро освобождает слот |
| CANCEL 0x114 | RBX = передача | Любой из двух владельцев может отменить передачу |

RAX возвращает dd_status. RCX и RDX должны быть нулевыми у вызовов без буфера.
При отказе RDX равен нулю. Код события окна равен 4, поле code различает
запрос текста (1) и предложение получателю (2). Сообщение содержит только
8-байтовый little-endian идентификатор. В очереди нет содержимого документа.

В каждом вызове отправитель/получатель определяется по билету выполнявшегося
процесса после реальной ловушки и возврата на доверенный корень. Адаптер
проверяет весь диапазон внутри RW/NX-страницы данных до передачи брокеру
доверенного адреса. При нехватке места можно повторить READ с подходящим
буфером. Если очередь источника полна, жест не публикуется. Если полна очередь
цели, брокер аннулирует уже выделенный номер и затирает текст.

Атомарность рассчитана на действующий однопроцессорный профиль, обработка
сериализована при IF=0. Срок от жеста до завершения составляет 2^37 отсчётов
TSC. Часы читает ядро, в том числе пока оба участника ожидают события.
Истечение срока, потеря прав или нарушение монотонности аннулируют состояние.
При завершении процесса очистка выполняется до повторного использования слота.
Просроченное уведомление в очереди может быть прочитано, но его номер больше
не открывает доступ к данным. После F10 передача сохраняет своих владельцев.

## Гостевая проверка

[Сценарий QEMU](../../tools/test_deep_drop_guest.py) загружает тот же ISO,
который прошёл обычную проверку рабочего стола. Два внешних пакета с различными
ELF собираются из [клиентского кода](../../tests/guest/deep_drop_72.S).
На специальном диске по LBA 2960 и 3000 лежат заголовки старого формата
STEA769 и отдельно содержимое пакетов. В EFI попадают только проверочные
значения и манифесты. Исходные Native-sample и Native-peer и их отпечатки
сохранены. На обычном диске действует прежний запуск. Вариант StyleFS читает
свои пакеты только через прежний механизм проверки ревизии файла.

F7 два раза запускает участников с испытательного диска. Клавиши A и B
добавляют буквы к выделению источника. Перенос мышью из левого окна в правое
предлагает текст. Щелчок по правому окну и Enter вставляют его в приватный
документ. V отображает контрольный цвет, рассчитанный приложением по всему
тексту. Escape отменяет предложение. Клавиша X вызывает контролируемое
исключение только во внешних испытательных клиентах.

Проверяющая программа сопоставляет порядок реальных INT 0x80, CR3 и регистров
по трассе QEMU с квитанциями ядра. При остановленной ВМ она независимо
обходит обе таблицы страниц и побайтно сверяет выделение, накопленный документ
и байт за его концом. Проверяются вывод в окнах, повтор READ, F10, отмена
с обеих сторон, #UD и принудительная остановка каждого участника через
«Процессы», срок жизни при ожидании и полный текст 1024 байта.

Испытательные файлы публикуются в артефактах Actions. Для воспроизведения
нужны QEMU 8.2.2, OVMF и инструменты обычной сборки.

```sh
python3 tools/build.py --arch x86_64 --desktop-owned-shell-865 --output build/drop72
python3 tools/test_deep_drop_guest.py --build build/drop72/x86_64 --output build/drop72-test
```

## Граница этапа

Служба передаёт копию в память получателя. Решение о вставке и сохранении
принимает само приложение. Гарантия однократной выдачи относится к одному
идентификатору. Устойчивость несохранённого документа при потере самого
процесса требует отдельного протокола. Активация свёрнутой цели, индикация
перетаскивания, файловые разрешения и потоковая передача остаются в дорожной
карте. Штатные приложения пока ожидают переноса на этот ABI.
