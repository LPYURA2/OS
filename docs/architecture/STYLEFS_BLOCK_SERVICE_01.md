## Owner requirement: large files (26.11.2026)
No arbitrary 64 MiB file or 1 GiB volume ceiling in the eventual practical system. Current StyleFS v1 64 KiB file, v2 64 MiB file / 1 GiB volume / 256 entries remain unchanged until verified new version; cannot just raise constants because v2 uses uint32_t sizes/addresses and limited extents and metadata. Proposed next format work: 64-bit file size and offsets, 64-bit block addressing end-to-end including storage driver, extent allocation and scalable directories; explicit backward compatibility and migration on a copy, no silent auto-format. Download, copy, import/export and Deep Drop must use bounded streaming buffers, 64-bit counters, progress/cancel, disk-full and interrupted-I/O recovery. Preserve original until target durable and validated; no claim of resumed transfer unless protocol and persisted checkpoints verified. Verify >4 GiB, fragmented/extents, disk-full, failure during commit, unchanged source, bounded RAM and cross-volume copy on provisioned test images, then supported real hardware. No promise of unlimited file size: actual capacity and checked format bounds apply. Existing ATA fixture is still narrow, not hardware support for large disks.
