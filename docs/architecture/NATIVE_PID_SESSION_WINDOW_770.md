# StyleOS 770 — реальные PID/CPL3 и модель окон пользовательских сеансов

Основа: принятый этап 769, `bdc98b0a3247117718fe7bafedeb94e09f76cfec`, GitHub CI 44943919612 PASS.
Задача: независимый аппаратный профиль x86-64, а не перенос под новый Desktop.

## Что реально делается

Отдельная EFI-сборка читает канонический `.tea` **с отдельного IDE-диска**,
проверяет SHA-256 и строгий ELF64, создаёт самостоятельный пользовательский
адресный корень, настоящий CPU-контекст и PID. После успешного `ps_register`
новый `native_session_hw_770` создаёт два тестовых пользовательских сеанса
через существующий `user_session_runtime`, привязывает каждый реальный PID,
проверяет соответствие реестровой записи аппаратному корню и создаёт окно с
`ws_open_app` в независимом системном `window_service`.

Тест проверяет:

- У каждого реального PID свой аппаратный корень, не SAFE, не корень соседа.
- Окно принадлежит PID, чужое управление запрещено.
- Активный сеанс видит только своё окно и свой снимок процессов.
- Смена пользователя блокирует прежний сеанс, не уничтожая чужой процесс.
- Перезапуск оконного сервиса сохраняет оба окна живых процессов.
- После реального CPL3 fault процесса A окно A удаляется, B продолжает работу.
- После аппаратного `EXIT` процесса B удаляется его окно; PID и привязки
  реестра могут быть удалены только после безопасного завершения контекста.
- Завершаются сеансы без зависших PID или окон.
- Изменённый `.tea` не получает ни PID, ни окна: отказ до первого CPL3.

Host ASAN/UBSAN + UEFI COFF тестирует ту же модель переходов независимо от
аппаратного теста. Полный CI продолжает регрессии desktop, F5/F8/F10, 2 дисков,
SAFE/CR3, CPL3/EL0, ARM64, периода 709–769.

## Строгая граница безопасности

**Это ещё не полноценное отделение приложений от Desktop.** Новые PID и
CPL3-контексты действительно запускаются **только в специальном тестовом
образе**. Сами `ws_window` — ядровая модель, не отрисованные независимые окна
в обычной графической оболочке; нет маршрутизации ввода/рисования через IPC.
Тестовые account-id (`0x770a`, `0x770b`) — маркеры, не авторизованные
пользователи. Системные таблицы stage 762/764/765 и транзакция stage 767
пока не включены вместе с реальным CPL3-контекстом в production Desktop;
отдельный DFO-ticket здесь не используется.

Реальная авторизация, пароли, защита домашних каталогов, ACL, файловая
система, пользовательский экран входа, оконные поверхности приложений,
IPC/syscall и корректная отчётность CPU/RAM остаются отдельными задачами.
Не показывать фальшивые показатели.

## Приёмка

```sh
python3 tools/test_native_session_hw_770.py --output build/native-session-770-host
python3 tools/build.py --arch x86_64 --test-native-tea-session --output build/session-770-efi
python3 tools/test_native_tea_770_guest.py --output build/native-session-770-qemu
```

Последняя команда требует реальный QEMU + OVMF и не имитирует успех.
Отдельный штатный ISO Desktop 770 является byte-identical по содержимому
предыдущему, поскольку GUI/основной загрузчик не менялись.
