# S863 PIO write transport candidate
Extends the already existing read-only S857 protocol without altering its source or allowlist. New runtime transport requires exact 4096-sector IDENTIFY geometry, valid FLUSH CACHE support, single-sector LBA28 within fixture, bounded alternate-status polling, 256 words, post-transfer completion, mandatory flush before further reads/writes. Sticky quarantine on partial or uncertain operations. Backend must independently enforce port identity, exclusive ownership and DMA denial for every callback including WRITE SECTORS/FLUSH CACHE; no raw port access or hardware claim from this module. The upper storage_runtime_863 contract adds root/epoch/device checks and post-flush byte readback. The failure state does not imply unchanged media. Host fixture tests exercise every callback failure in write and flush, unsupported flush, timeout, out-of-range and pending-flush denial. GCC/Clang sanitized tests and COFF compile added to existing bootstrap workflow without removing any prior tests. No ordinary image changes. Next bind both modules to the fixed disposable PIIX3 IDE guest fixture with same-boot QMP attachment/port/DMA checks and distinct reboot readback, then integrate ordinary shell storage. Do not give a general ATA grant or accept KFA. Prior exact SHA RTC and storage CI still running when this candidate was prepared. Main and accepted branches unchanged.
