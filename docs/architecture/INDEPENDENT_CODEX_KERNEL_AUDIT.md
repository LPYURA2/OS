# Независимая проверка Style Kernel — задание Codex

Запускать после полного завершения всех обязательных CI и сверки KFA-01..12. Использовать только точный финальный SHA ветки feature/styleos-kernel-reacceptance (или следующей исправленной ветки) и соответствующие артефакты. Не считать SHA этого документа автоматически принятым.

Режим: независимый read-only аудит, без редактирования исходников, коммитов, merge, релизов или изменения тестов. Изучить AGENTS.md, docs/PROJECT.md, docs/architecture/KERNEL_FINAL_ACCEPTANCE.md, docs/architecture/KERNEL_REACCEPTANCE_NATIVE_STOP.md, фактические CI, raw UART/QMP/CPU traces, манифесты и SHA256. Проверить достаточность доказательств, а не только зелёные статусы.

Приоритеты:
1. Ошибки ядра, при которых пользовательский процесс способен вызвать зависание/падение системы, нарушить изоляцию, повредить чужой процесс или состояние ядра. Привилегии CPL3, исключения, syscall, возврат, RSP/RIP/RFLAGS, IRQ/IST, аппаратный контекст FP/SIMD.
2. Планировщик, прерывания, конечность операций, принудительное завершение READY-процесса и гонки/границы применимости, идентичность PID/handle/root/generation, переполнения счётчиков.
3. Память, права страниц, алиасы, очистка/повторное использование, границы ресурсов, освобождение окон, сессий, IPC и отсутствие доступа по старым идентификаторам.
4. Boot/EBS, ACPI/PCI/DMA, реальный аппаратный допуск, отсутствие диагностических разрешений и заглушек в ordinary no-catalog ISO, воспроизводимость исходников/ISO.
5. Полнота тестов, негативные сценарии, raw evidence, независимое воспроизведение возможных дефектов. Не выводить SMP/AMD/Intel на физическом железе/VirtualBox из Q35 TCG одного vCPU, не выдавать привилегированный тест за пользовательский интерфейс.
6. Объективная оценка зрелости и ограничений; отдельно предложить измерения производительности/системных требований. Не изобретать метрики.

Отчёт: точный SHA, окружение, фактически выполненные команды и результаты, дефекты с приоритетом P0–P3, файлом/строкой, условиями воспроизведения, ожидаемым/фактическим результатом, влиянием и минимальным предлагаемым исправлением. Отдельно подтверждённое, предположения, непройденные/непроверенные области. Заключение: готов/не готов к принятию в явно ограниченном профиле; перечислить блокеры. Никаких абсолютных гарантий. Код не менять; владелец и основной чат решают, что исправлять. Не начинать файловую систему или новые функции до решения.
