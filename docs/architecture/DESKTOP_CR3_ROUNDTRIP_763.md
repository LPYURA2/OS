# StyleOS 763 — аппаратный возврат на исходный CR3 (ограниченный эксперимент)

База: 762 (`7b40d3aac059e83c2e7340a9be4bc8bc421b1096`).
Ветка: `feature/styleos-cr3-roundtrip-763`.

## Что действительно проверяется

Только отдельный **x86-64 тестовый UEFI-образ**, не обычный Desktop:

1. Существующий T-P1.4 admission проверяет выделенный в BSS загрузочного
   образа набор таблиц и свой контрольный блок — весь размер, резервирование,
   исключения, соответствие текущему read-only walk унаследованного CR3.
2. Удостоверяются режим CPU, NXE, PAT, исходное адресное пространство,
   полный отображённый образ и стек, GDT/IDT и рабочие страницы журнала.
3. Старый конструктор PG строит отдельные страницы, а QEMU действительно
   исполняет `mov CR3`, после чего проверяются регистры и фактические PTE,
   запись/чтение по новому алиасу данных.
4. Режим 763 дополнительно **возвращает CR3 на прежний физический корень**,
   сверяет адреса, регистры CPU и доступность image/code/IDT/GDT. Критические
   аппаратные данные включены только после проверки, IF остаётся выключен.
5. Верификатор требует **две разные фактические CR3**, оба наблюдения CPU,
   реальный изменённый алиас и контролируемое завершение теста в QEMU; анализ
   прежних разделов PE и дескрипторов независим от выводимой строки PASS.

## Принципиальные ограничения

- В этом этапе проверяются известные **T-P1.4 таблицы PG**, а не новые
  `dvm_storage` из этапа 762. Нельзя заявлять, что SAFE/USER ROOT 762 сейчас
  способны загрузить Desktop без page fault.
- Контрольный образ **в CPL0**, здесь нет настоящего переключения на
  пользовательское `.tea`, дополнительных PID, syscalls или таймера.
- Имеющиеся UEFI-таблицы остаются на месте, память не передаётся PMM и не
  освобождается; гарантия действительна только для узкого тестового режима.
- Нельзя переносить этот тест в обычный Desktop до полного proof его
  зависимостей: PE sections/W^X, IRQ/IDT, TSS/GDT, все стеки, framebuffer,
  MMIO, таблицы процесса, кэш/пат и жизненный цикл страниц.
- Проценты CPU и потребление RAM остаются неподтверждёнными.

## Выполнение

```sh
python3 tools/test_desktop_vm_stage.py --output build/dvm-host
python3 tools/test_paging_roundtrip.py --output build/763-roundtrip
```

Второй тест требует настоящий `qemu-system-x86_64`, OVMF_CODE/OVMF_VARS,
собирает отдельный образ и проверяет UART + PE/SHA. Это **не эмуляция
результатов в host-тестах**. Неудача QEMU/OVMF означает NOT PASS.

Далее нужен независимый x86-64 desktop map owner с собственной выделенной
памятью таблиц, формальное покрытие PE и активных устройств, и отдельный
подконтрольный запуск неиспользуемого пользовательского root без смены
производственного Desktop. Уже после — запуск `.tea` через изолированный
CPL3-контекст, реестр PID и копирующий syscall broker.
