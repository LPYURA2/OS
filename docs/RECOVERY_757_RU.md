# StyleOS — этап 757: системное предустановленное приложение

## Решение владельца

«Документы» — **системное приложение, предустановлено при установке ОС**,
но **независимо от оболочки и рабочего стола**. Не «вшивать» в desktop shell,
не делать редактор частью ядра. Встроенное приложение ≠ встроенный код.

## Реализовано в исходниках этого этапа

1. `installer/system-apps.json` — декларация системного комплекта. Одна
   запись `styleos.documents`, автоматически предустанавливается в system
   volume, самостоятельный процесс, пункты запуска через реестр.
2. `tools/tea_package.py` — общий (не зависящий от «Документов») контроль ELF
   x86-64 с отказом для динамического линкования, W+X, плохой геометрии
   сегментов, исполняемого стека и неподдерживаемой архитектуры.
3. `tools/system_apps.py` — эталонный установщик на хосте: проверяет ZIP
   `.tea`, SHA256, ABI, ID, манифест, размеры; сохраняет поколение
   системных приложений с атомарным `current`. Повторная установка
   идемпотентна, предыдущая версия сохраняется для отката.
4. `tools/build_preinstall_bundle.py` — детерминированный ZIP для
   **разработческого** предустановочного комплекта, с понятной маркировкой
   NOT BOOTABLE/NOT 744. Поддерживает проверку и развёртывание комплекта
   в пробную системную папку.
5. Тесты обновления/отката, повреждений, ссылок/путей, сохранности данных,
   общего ELF и повторяемой сборки. Все результаты — только host-тесты.

## Нельзя объявлять готовым

- Нативный установщик 744 не умеет читать этот набор.
- Независимый загрузчик x86-64 ELF и процессная изоляция на нужном гостевом
  desktop не восстановлены и не протестированы.
- Не реализована цифровая подпись `.tea` (SHA256 не аутентификация издателя),
  поэтому production staging намеренно **BLOCKED**, разрешён только dev.
- UI 14 экранов и полноценные DOCX ещё не восстановлены.
- Загрузка нового ISO в QEMU/VirtualBox, полноценная регистрация и запуск
  «Документов» в ОС — NOT RUN. **Нового загрузочного ISO нет.**

## Архитектурное требование к выпуску

В финальном ISO StyleOS должна содержать самостоятельный `Documents.tea` на
системном разделе с регистрацией через generic registry. При установке он
должен быть доступен сразу, без магазина, сети и действия пользователя.
Перезапуск ОС, установка, обновление и откат не должны удалять личные
документы. Встроенность в поставку ОС не даёт прав ядра или постоянного
доступа ко всем файлам.

## Что далее

Создать нативные службы `SystemAppRegistry`, `AppProcessLoader`, `FileBroker`
и `WindowBroker` на *актуальных* исходниках системы с документацией
версионированного ABI; восстановить портированное GUI и все 14 экранов;
включить пакет в сборку установщика и доказать через QEMU свежий ISO,
все функции редактора, перезагрузку и независимые другие приложения.
Контрольную 744 и предыдущие GitHub-ветки не изменять.
