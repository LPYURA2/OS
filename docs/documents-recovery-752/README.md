# StyleOS Documents — recovery source checkpoint 752

**Статус: восстановление исходников, а не готовая новая сборка ОС.**

Исходной контрольной точкой является пользовательский архив
`StyleOS-744-Documents-Intermediate.zip` (SHA256 отдельного ISO указан
в `docs/744-binary-checksums.txt`). Контрольный ISO **не изменяется**.
Исходный код соответствующей версии в доступных файлах утрачен; доступная
публичная ветка StyleOS старше версии 744. Образ 744 содержит экземпляры
`BOOTX64.EFI`, но не содержит отдельного файлового объекта `Documents.tea`.
Проверка бинарника не восстанавливает реализацию редактора.

## Что есть в этом исходном дереве

- `modules/documents/review.c` — офлайн-подсказки и ограниченная модель
  отслеживания вставок/удалений от этапа 751;
- `modules/documents/model.c` — начатая независимая модель документа:
  UTF-8, выделение, изменение текста, диапазонные комментарии, размеры
  листа и поля; это **не** GUI и **не** полнофункциональный DOCX-редактор;
- `tools/audit_744.py` — неисполняющая структурная инспекция ISO9660,
  FAT16 и совпадения двух экземпляров EFI внутри контрольного ISO;
- `tests/` — автономные тесты.

```sh
sh tools/test_restore.sh
sh tools/test_restore.sh /path/to/StyleOS-Install-x64.iso
```

## Осталось для пользовательской сборки

1. Воссоздать **собираемый** исходный десктопный профиль StyleOS без
   регрессий относительно контрольной 744. Не заменять рабочий стол
   старой версией из GitHub.
2. Создать настоящий `Documents.tea`, поддерживаемый **системным**
   загрузчиком `.tea`, а не только хостовый SDK preview.
3. Реализовать остальные функции по `StyleOS-Documents-Full-Concept.pdf`,
   в том числе разметку, сохранение и открытие DOCX, PDF, печать,
   проверку, автоматизацию, контекстное действие «В заметки».
4. Собрать новый установочный ISO с предустановленным `Documents.tea`,
   проверить холодную установку, открытие/изменение/сохранение файлов,
   переносимость диска данных, регрессии QEMU. VirtualBox — отдельно.
5. **Только после этого** выдавать сборку и заявлять готовность приложения.

`main`, прежние ветки, Portable-os, контрольный образ и диски данных
не изменены. Каждый последующий этап — новая ветка, полные исходники
и воспроизводимые тесты; готовая сборка — отдельный обязательный результат.
