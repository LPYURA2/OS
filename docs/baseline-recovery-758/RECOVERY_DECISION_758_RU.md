# StyleOS — точка восстановления 758 / 730 как рабочий эталон

**Решение владельца (21.11.2026):** исходить из работоспособного тестового образа **730** как поведенческого эталона ОС, из образа **744** брать дополнительные функции «Документов», а полный интерфейс делать **строго по StyleOS-Documents-Full-Concept.pdf (14 экранов, 8 вкладок)**. Все родные приложения только `.tea` — в том числе системные, предустановленные «Документы». `.sapp` не переносить в новый native ABI. Android/Windows — будущие отдельные режимы совместимости, не нативные форматы StyleOS.

## Что действительно доступно

- `StyleOS-730-Test.zip` содержит только `START.txt`, ISO, дополнительный VDI, изображение установщика и SHA256SUMS. В ZIP **нет исходного кода**. Корректность архивных байтов и ISO/EFI подтверждена `tools/check_baseline_730.py`.
- В 730 PE `BOOTX64.EFI` присутствуют ссылки `Documents.sapp`, `Explorer.sapp`, `Editor.sapp`, `Notes.sapp`, `PROCESS START pid=` и диагностические строки перестройки оболочки F10. Это бинарные *признаки*, а не доказательство процесса в виртуальной машине.
- `StyleOS-744-Documents-Intermediate.zip`: более поздний бинарный контроль функциональности документов. Там встречаются `Documents.tea` и упакованные в PE данные; самостоятельный надёжно проверенный пакет в ISO не найден. **Исходный код 744 в ZIP отсутствует.**
- GitHub `LPYURA2/OS` доступен, но подтверждённого исходного коммита, из которого собрана именно 730, пока не найдено. Доступная ветка `feature/styleos-desktop-v0` более ранняя, нельзя выдавать её за точный исходник 730.
- Существующий код 757: модель текста, некоторые функции редактирования, ограниченные TXT/DOCX, экспериментальный `Documents.tea`, разработческий каталог предустановки. **Не запускается внутри гостевой StyleOS.**

## Правило восстановления

1. **Не патчить PE/ISO бинарно.** Никаких догадок о смещениях кода, никаких изменений контрольных 730/744.
2. Воссоздать **собираемую системную базу**, результат которой проходит регрессионные тесты по поведению 730. Возможность идентичного восстановления 730 из двоичного ISO не гарантирована; требуется исходный код или повторная реализация.
3. Отделить системные службы (процессы/файлы/окна) от программ. **F10 перезапускает оболочку, приложения сохраняют PID, состояние и несохранённый текст.**
4. В родном registry, installer и launcher принимать **только `.tea`**. Старые `.sapp` могут служить исключительно историческим образцом реализации, без runtime compatibility по умолчанию.
5. «Документы» — **системное приложение с отдельным процессом**, установленное в системный раздел *в ходе установки ОС*. Оболочка получает запись из реестра; код редактора не линкуется в shell или kernel.
6. Для файлов использовать host/broker-granted tokens, атомарное сохранение и обособленный диск пользовательских данных. Обновление системного раздела не стирает данные.
7. Восстановить все функции **реально работающими**, без UI-кнопок, не ведущих к действию; все 14 экранов строго по утверждённым макетам.

## Контроль после сборки новой ISO (пока НЕ выполнен)

- Чистая установка в QEMU с двумя виртуальными дисками; проверить отсутствие изменений исходных контрольных образов.
- Старт рабочего стола; запуск Проводника, редактора, заметок и `Documents.tea`; независимые PID и память.
- Набрать несохранённый текст в четырёх приложениях, снять PID, нажать F10, проверить живые процессы и состояние.
- StyleFS v2: фоновое копирование между томами, прогресс, отмена, одновременный ввод текста, сохранность каталога.
- Все 14 экранов «Документов», команды и форматирование, создание/открытие/сохранение/повторное открытие DOCX, TXT; проверка DOCX сторонним парсером; меню выделения «Отправить в заметки» создаёт заметку **рядом с исходным файлом**.
- `Documents.tea` присутствует как отдельный объект на системном томе после установки; `.sapp` как нативные приложения отсутствуют. Откат без потери пользовательских файлов.
- Проверка при перезагрузке, при повреждённых пакетах, отказах ввода-вывода; тесты безопасности. VirtualBox — отдельная фактическая проверка.

## Результат именно этапа 758

Создан read-only инструмент `tools/check_baseline_730.py` для сверки контрольных ZIP/ISO/EFI и политики формата `.tea`; 14 тестов контракта прошли, архивы 730 и 744 подтвердились без изменений. Хостовый регрессионный прогон 757 также прошёл.

**Это не реконструированный исходник 730, не 758 ISO, не тест запуска в QEMU, не готовые «Документы».** Образ 730 и код приложения нельзя безопасно объединить без восстановления/создания актуального исходного дерева системного загрузчика и оболочки. Не выдавать ZIP с инструментами за новую рабочую ОС.
