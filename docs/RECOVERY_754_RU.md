# StyleOS — «Документы», восстановление 754 (исходники, НЕ новая ОС)

## Назначение

Контрольная версия системы **744** (ISO SHA-256 `011dd3560e8d232b00201623443d9a09b0c67e03227b66504312a31f75e285ae`) неприкосновенна. Этот этап развивает отдельное приложение, не переписывая код рабочего стола. Исходники должны публиковаться в новой ветке `feature/styleos-documents-recovery-754`.

Результат — **библиотека/интерфейс приложения для хостовых тестов**, а не готовая `Documents.tea`. Не проводить установку в StyleOS на основании этого архива.

## Что добавлено (реальный код)

1. `include/styleos/documents_app_gateway.h`, `modules/documents/gateway.c`: приложение запрашивает операции чтения/атомарной замены через переданный системой файловый токен. Нет доступа к файловым каталогам и функциям оболочки напрямую. Неуспешный запрос не стирает несохранённый документ. Два экземпляра редактора изолированы по состоянию.
2. `include/styleos/documents_import.h`, `modules/documents/import.c`: ограниченный импорт DOCX на базе несжатого ZIP, совместимый с собственным экспортёром предыдущего этапа. Содержит обработку XML text/entity, табуляций, абзацев, свойств страницы, проверку CRC и центрального каталога. Сжатые DOCX из Word, сложная вёрстка, картинки, стили и история изменений ещё не поддерживаются — при неподдержанном вводе возвращается ошибка, а активный текст остаётся нетронутым.
3. `include/styleos/documents_ui.h`, `modules/documents/ui.c`: app-owned модель области окна с тёплой страницей, графитовой панелью, янтарным акцентом, 8 вкладками и 14 идентификаторами экранов по утверждённому PDF. Ввод UTF-8, Backspace, смена A4/Letter и запросы Ctrl+N/O/S/P реально обрабатываются интерфейсом приложения. Прочие видимые команды пока не активны. Это **сценарий команд отрисовки**, не установленное окно StyleOS и не вся готовая графика.
4. Host-only предпросмотр в `tools/render_documents_ui.py`. Он визуализирует команды и не является скриншотом из гостевой ОС.

## Что не выполнено

- Нет исходников и бинарного адаптера системного хоста 744. Брокер не подключён к файловой системе, `.tea`-загрузчику или графическому диспетчеру.
- Нет настоящего устанавливаемого `Documents.tea` или нового ISO. У `styleos.system-module-v1` нет документированного исполняемого API, который можно безопасно реализовать для существующей 744 на основе данных архива.
- Не закончены девять функциональных разделов из 14 макетов: форматирование, объекты, ссылки, автоматизация, полноценная орфография, рецензирование DOCX, печать и т.д.
- Не запущены QEMU/VirtualBox/Termux: QEMU отсутствует в доступном окружении, а новый гостевой образ не собран. Хостовые тесты не являются приемкой StyleOS.
- Не внесены изменения в `main`, `LPYURA2/Portable-os`, исходный ISO 744 и существующий диск данных.

## Тесты

`sh tools/test_restore.sh` — GCC и Clang, исторические проверки, модуль DOCX, файловый шлюз, 14 маршрутов UI и 1200 воспроизводимых пограничных/повреждённых DOCX, плюс 10 Python unit tests. Адресная/undefined-behavior проверка новых модулей через clang sanitizers — PASS. Самостоятельная библиотека пересобирается повторно. Нет тестов в настоящей гостевой ОС.

## Что делать дальше

Полное восстановление требует получить или воспроизвести системный исходный GUI/app-loader для 744 в отдельной ветке. В этой основе нужны проверяемые интерфейсы от shell к app: окно/отрисовка, ввод, файловые токены, IPC и установка `.tea`; после этого можно соединить модули и дописать UI/функции по альбому. Не заявлять этот этап завершением «Документов» и не выдавать прежний ISO за обновление.
