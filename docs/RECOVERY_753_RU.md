# StyleOS — проверенная точка восстановления 753 (исходники, не ОС)

**Нельзя объявлять эту ветку полноценной сборкой StyleOS или готовыми «Документами».**

## Достоверные результаты

- Контрольный ISO 744 не менялся. Исходный EFI содержит шесть встроенных
  `manifest.json` для формата `styleos.tea.sdk-v0`, включая
  `styleos.documents` с заявленным ELF-пayload 57464 байта.
- Проверка содержимого показала, что манифест `styleos.documents` читается,
  однако SHA-256 и CRC указанных внутри образа ELF-байтов не сходятся
  с записанными значениями. Это **не доказательство**, что установка в
  существующей 744 сломана, но явный запрет выдавать вырезанный ELF как
  проверенный готовый `.tea`.
- Написан и проверен read-only инвентаризатор `tools/embedded_tea_catalog.py`.
- Восстановлена экспортная часть DOCX для **обычных текстовых документов**:
  экспорт из data-model в ZIP_STORED OOXML (`word/document.xml`), UTF-8,
  экранирование XML, абзацы, табуляция, A4/Letter, ориентация и поля.
  Сформированный DOCX успешно открыт независимым `python-docx`.
- C11 модель документа и базовый grammar/tracked-edits engine продолжают
  проходить самостоятельные unit/stress-тесты.

## Чего нет

- Не восстановлен весь исходный код версии 744; desktop shell-код и
  `Documents` GUI по альбому отсутствуют.
- Нет связывания с живым `Documents.tea`, системной инсталляции и запуска
  этой новой библиотеки в гостевой StyleOS.
- Нет полноценного чтения сторонних DOCX, стилей, таблиц, рисунков,
  комментариев OOXML, PDF, механизма печати и автоматизации.
- Нет созданного ISO 753, реальных QEMU/VirtualBox проверок и пользовательской приёмки.
- В этом контейнере отсутствует `qemu-system-x86_64`; факт загрузки 744
  здесь не подтверждался.

## Безопасная последовательность

1. Восстановить исходный desktop и native `.tea` runtime, эквивалентный 744,
   **не заменяя** работающий образ старым кодом GitHub.
2. Подключить заново DOCX/text/review API к системному приложению и
   воспроизвести все четырнадцать экранов из
   `StyleOS-Documents-Full-Concept.pdf` с настоящим поведением.
3. Все пользовательские приложения оформлять в `.tea`; ничего не
   внедрять монолитно ради обхода формата.
4. Собрать чистый boot ISO и `Documents.tea`, проверить в QEMU, затем дать
   пользователю реальную сборку с контрольными суммами и тестами.

`main`, исходная 744, виртуальные диски и рабочий стол не изменены.
