Последний принятый этап — 798 (перед объявлением принятия проверить точный
финальный SHA, полный SUCCESS GitHub Actions и исходные журналы). Ветка
`feature/styleos-pci-mmio-extent-attestation-798`, исходная принятая версия 797
`f07cf08c95da7175bac6dcf6cc7b03c5bb45022d`.

Прочитай AGENTS.md, docs/PROJECT.md, docs/NEXT_CHAT_798.md,
docs/architecture/PCI_MMIO_EXTENT_CENSUS_798.md и
docs/design/APPROVED_UI_REFERENCES.md.

В 798 подготовлен fail-closed реестр PCI MMIO по аппаратным журналам трёх
раздельных QEMU-VM, заново запущенных в одном CI. S795 измерил VGA BAR0
`0x80000000..0x81000000`, 16 МиБ, и восстановил состояние BAR/command.
S796 обнаружил 8/10 BAR в обычной/мостовой конфигурации, но их длины
остались неизвестны: отдельное измерение S795 не переносится на другие
загрузки. В мостовой конфигурации по окнам пересылки доступны только
верхние пределы 2 МиБ и 512 МиБ, НЕ фактические размеры BAR.
S797 подтвердил только маршрутизацию начальных адресов. Никаких разрешений
на производственный CR3 или MMIO stage 798 не выдаёт.

Сейчас фундамент НЕ завершён. Следующий этап — 799: изолированное безопасное
измерение диапазонов BAR у выбранных дочерних устройств за PCIe-мостом,
проверка полного попадания в окна, строгие тесты восстановления PCI.
Никаких таких записей в конфигурацию PCI при обычном Desktop.
Затем PAT/MTRR, IRQ/APIC, DMA/IOMMU/UEFI runtime, полноценная производственная
карта памяти и аппаратное подтверждение Desktop + приложения + файлы.

После фундамента: доделать «Процессы» с реальными PID/CPU/RAM/управлением,
полностью независимые .tea, пользователей/вход по утверждённым макетам,
StyleFS и Проводник по `StyleOS-Explorer-Mockups.pdf` (раздел «Быстрый доступ»).
