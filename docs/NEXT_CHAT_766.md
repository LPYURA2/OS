## Что делать дальше

настоящим PID, пользовательским сеансом и окнами через атомарную транзакцию.
Выполнить обязательный аппаратный аудит root/kernel mappings (TSS/GDT/IDT,

многозадачность, учёт RAM и CPU; затем система аккаунтов и экран входа
**строго по утверждённым макетам**.

Каждый этап в НОВОЙ ветке, `main` не менять. Архивировать полный SOURCE,
ISO из успешного QEMU-CI, SHA, тесты и эту точку продолжения. Не выдавать UI
session ID за процессный PID или модель пользовательского сеанса за защиту
данных. Не изменять действующий рабочий стол и `.tea` без регрессий. Не
терять вторую data volume, Deep Drop и восстановленную базу 709–730.
