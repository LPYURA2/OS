# ADR-001 — Единая ISA для Termux ↔ Proteus (решение открыто)

**Дата:** 12.11.2026  **Статус:** не утверждено владельцем.

## Проблема
Текущий M32: нестандартные 8-байтные команды, 33 опкода, CPU/ядро ASM. M8: собственная 8-битная ISA, 25 опкодов. Они НЕ совместимы и не исполняют один kernel.bin.

Нужно выбрать одну ISA, которую Python эмулирует и которую можно воспроизвести в цифровой логике Proteus. При переносе на x86/ARM останется один код ядра на уровне исходников, но бинарники будут другими.

## Вариант А: развивать экспериментальную M32
Плюсы: существующий рабочий код, низкий порог продолжения. Минусы: придётся проектировать компилятор C/ABI; нестандартная 8-байтная ISA утяжеляет логическую схему и плохо подходит для современного программного стека.

## Вариант Б: RV32I, затем опционально RV32IM (предложение)
Плюсы: открытая фиксированная ISA, доступные компиляторы C/C++, документация, легче переносить гостевую ОС на другие CPU. Минусы: потребуется новая модель CPU и переписывание bootstrap, ядра и оболочки; полноценная схема в Proteus сложнее, чем M8.

## Вариант В: M8 → M16/M32
Плюсы: сохраняем собственную аппаратную линию. Минусы: существенная разработка ISA/компилятора, непредсказуемость совместимости и времени; 8-битный M8 с 32 КиБ RAM не подходит для современного GUI/FFI.

**Рекомендация для обсуждения:** RV32I как основная ветка ОС, M8 оставить независимым стендом логических схем. Пока это рекомендация, не утверждение, и экспериментальная v0.3 не является переносом на RV32I.
