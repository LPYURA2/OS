# StyleOS — утверждённые макеты. Регламент изменения UI

Решение владельца, 21.11.2026: **не изменять текущую цветовую палитру и рабочий стол**. Оставшиеся интерфейсы должны точно следовать утверждённым макетам. Цвет PDF-макета не является разрешением менять действующие цвета ОС. Не менять kernel/desktop_shell.c и kernel/desktop_draw.c для этого этапа.

Стандарт: предустановленное независимое Documents.tea, не часть оболочки. Дополнительную синюю тему PDF не переносить автоматически поверх текущей палитры владельца.

## Текущий узкий этап

StyleFS v2 получил API пошагового копирования **одного файла между двумя уже смонтированными томами** с отложенной публикацией каталога, CRC, отменой и контролем поколения метаданных. Речь об уровне ФС, а **не** о готовом пользовательском окне, копировании папок, физической обработке переподключения диска или запуске двух томов в госте. Ни desktop_shell.c, ни desktop_draw.c, ни палитра, ни макеты не изменены. Следующим отдельным этапом интегрировать реальную дисковую топологию и проводник строго по PDF.
