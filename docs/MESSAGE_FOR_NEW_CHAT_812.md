# Сообщение для нового чата — StyleOS после 812

Продолжаем разработку StyleOS, репозиторий `LPYURA2/OS`.

Принятая база до 812: этап 811 на
`16f03f5f182592f70b3271358cfcd9e8ab2e46c2`,
GitHub Actions https://github.com/LPYURA2/OS/actions/runs/45164125712.

Рабочая ветка 812: `feature/styleos-pci-bridge-ivhd-812`.
Перед изменением кода проверь актуальный точный SHA и завершённый
GitHub Actions для **него**, не для промежуточного коммита. Скачай полный
архив исходников успешного CI, штатный ISO, исходные UART/JSON и
SHA256SUMS; не принимай этап, если последняя проверка не SUCCESS.

Прочитай `AGENTS.md`, `docs/PROJECT.md`,
`docs/architecture/PCI_REQUESTER_SCOPES_811.md`,
`docs/architecture/PCI_BRIDGE_IVHD_812.md` и
`docs/NEXT_CHAT_812.md`. Сохраняй утверждённые макеты.

В 812 добавлены изолированные тестовые средства:
обход PCI-мостов и многоступенчатых путей Intel DMAR, bounded AMD
IVHD SELECT/RANGE/ALIAS/EXT и учёт IVMD-исключений,
модель аппаратной топологии, проверка входных данных, настоящие QEMU
Intel/AMD/без IOMMU, QEMU с PCIe root-port и отдельный реальный
двухуровневый мост (root-port → PCIe-to-PCI bridge), negative UART и
ASAN/UBSAN/COFF. Многоступенчатый Intel DMAR device scope проверен
синтетическим модельным тестом; полный аппаратный маршрут Requester ID
к контроллеру IOMMU НЕ подтверждён.

DMA-домены, реальные аппаратные deny/allow, fault logging,
инвалидации, все PCI-сегменты, полный AMD IVHD, UEFI runtime,
включение собственного production CR3 и интеграция штатного ядра
с Desktop, процессами, .tea и файловыми операциями остаются впереди.
Любое DMA-разрешение запрещено. **Фундамент StyleOS НЕ завершён**.

Следующий этап проводить в НОВОЙ ветке от принятого 812,
но только после полной проверки. Дальше: физически безопасная
идентификация IOMMU ownership → DMA-домены с настоящим deny/allow →
UEFI runtime и production CR3 → комплексная аппаратная приёмка
обычного ядра и Desktop → полные «Процессы» → независимые .tea →
пользователи и экраны входа/блокировки → StyleFS/Проводник с
«Быстрым доступом» → установщик .tea, App World, сеть, браузер, звук, VPN.

Не меняй main, принятые ветки, существующий Desktop, его палитру
или утверждённые макеты. Для каждого этапа нужны полный ZIP
успешного CI, ISO, аппаратные логи, точный SHA, ссылка Actions,
технический отчёт, точка продолжения и сообщение новому чату.
