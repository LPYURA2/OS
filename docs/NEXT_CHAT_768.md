# StyleOS — точка продолжения после 768

Дата: 21 ноября 2026. Репозиторий `https://github.com/LPYURA2/OS`.

База: этап 767, `07c9ebd2b4637eca9e5cbc5a837690ed0501a371` (CI PASS,
run `44932246596`). Новая ветка: `feature/styleos-native-tea-cpl3-768`.
**Финальный SHA/CI** сверить с фактическим HEAD ветки и артефактом GitHub;
не использовать неподтверждённые значения из промежуточных ответов.

В 768: отдельно собранный и упакованный canonical `.tea` ELF64 запускается
в настоящем тестовом x86-64 CPL3: код из ELF копируется в собственную BSS
user RX страницу; PID от реестра, YIELD → возобновление → EXIT,
с сохранением регистров; второй тестовый процесс отдельно fault изолирован.
Полная спецификация: `docs/architecture/NATIVE_TEA_ELF_CPL3_768.md`.

**Границы:** `.tea` распакован и проверен *на host при сборке*, а не внутри
обычной guest ОС. Это не работающий Desktop `.tea` launcher, не системные
users/ACL, не production MMU/CR3, не syscall/IPC. Не выдавать макет UI за
реальные PID и не отображать CPU/RAM, пока не подключено измерение.

**769:** guest disk .tea reader/verifier → mapped executable ELF →
`native_launch_stage` 767 → PID → session → window, с аппаратным QEMU
доказательством и rollback. Далее Processes.tea и login по макетам.

**Нерушимые правила:** каждый этап — новая ветка от принятого SHA, не менять
`main`, не трогать рабочий стол и два диска; никакой подмены PID
или фальшивых метрик. По завершении дать исходники ZIP точного CI SHA,
загрузочный Desktop ISO успешного CI, архив тестов, этот текст для нового чата.
