## Что действительно сделано в 767

Kernel-only транзакция связывает **сначала подготовленный контекст** с
настоящим PID (`dpr_service`) -> конечной страницей lease (`dfo_owner`) ->
выбранным сеансом (`usr_runtime`) -> окном (`ws_service`).

Есть обработка сбоев/отката, отклонение чужого родителя, неправильных корней,
переполнения окон, неправильного контекста, сессий; очистка окон, PID и
процессной записи; отзыв таблиц fail-closed. Существующий GUI не изменён.

## Что ещё НЕ сделано

- Процесс `Editor.tea`, `Processes.tea` и другие не запускаются как реальный
  CPL3 ELF в обычном Desktop. Модуль связан с EFI, но не вызывается.
- Ещё нет пользовательского ELF-загрузчика/собственного безопасного root,
  общесистемного PMM, syscall/IPC, вытесняющего scheduler, CPU%/RAM.
- `user_session_runtime` не равен настоящей авторизации, защите файлов,
  домашним папкам или экрану входа.
- Старые `desktop_sessions` «PID» — служебные UI IDs, НЕ реальные PID.
- Отзыв lease не освобождает физические страницы и не проверяет доказательства
  отсутствия чужих CPU references: это задача доверенного arch backend.
