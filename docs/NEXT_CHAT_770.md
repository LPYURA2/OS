# StyleOS — точка продолжения после 770

Репозиторий: `LPYURA2/OS`. Ветка: `feature/styleos-real-pid-user-session-window-770`.
Приёмочный SHA и GitHub Actions CI вписать после реального успешного прогона;
никакие предварительные статусы не считать PASS.

## Принято ранее

- 768 `4e15acc37e7ab09f3cb73f4685ce283f5dd9f9a9` — отдельный ELF64 `.tea` в CPL3 (build-extracted).
- 769 `bdc98b0a3247117718fe7bafedeb94e09f76cfec` — гостевое чтение канонического `.tea` с IDE-диска, реальное CPL3, отказ на подделке; CI `44943919612` PASS.
- 770 — настоящее аппаратное использование реестра PID + root вместе с ядровым `user_session_runtime` и `window_service` в отдельном тестовом профиле. Не утверждать production-выполнение до независимой проверки.

## Следующие задачи

1. Следующий этап создавать **в новой ветке** от точного принятого SHA 770.
2. Реальный kernel-owned loader для обычной Desktop, с жизненным циклом
   физических страниц, DFO lease/реальным safe-root, verified CPL3, syscall и
   поверхностью окна вне оболочки (пройти негативные тесты).
3. Системный «Процессы»: реальные PID и состояния, разные сеансы; данные
   CPU/RAM только после измерения, protected kernel tasks; проектировать по
   утверждённым макетам. Не подменять kernel PID номерами desktop_sessions.
4. После этой цепочки: учётные записи, безопасное хранение учётных данных,
   блокировка/смена сеансов, вход по утверждённому **макету** из библиотеки;
   до полной файловой изоляции не выдавать выбор пользователя за security.
5. Довести StyleFS: транзакционность, восстановление, ошибки диска,
   разграничение владельцев/ACL и домашние каталоги, совместимость двухтомной
   модели (системный диск заменяемый, данные сохраняются).
6. Довести Проводник до финального макета: «Быстрый доступ», без
   «Рекомендованного», работающие операции с файлами, контекстное меню,
   системные диалоги, копирование/переименование/перемещение и безопасное
   поведение при ошибках.

Правила: `main` не менять, старое не удалять, каждый этап в новой ветке;
после каждого этапа — полный ZIP исходников **точного CI SHA**, ISO из
успешного CI, полный протокол и точка продолжения. Если CI красная —
исправить и повторить, не выдавать этап за принятый.
