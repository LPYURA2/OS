# StyleOS — точка продолжения: восстановление «Документов» 754

## Исходное состояние
- Контрольная 744: `StyleOS-744-Documents-Intermediate.zip`, SHA-256 установочного ISO `011dd3560e8d232b00201623443d9a09b0c67e03227b66504312a31f75e285ae`. Не изменять.
- Приёмка 744–749 в GitHub не восстанавливает исходный GUI: исходники 745–749 недоступны.
- Публичная линия на GitHub: `feature/styleos-documents-recovery-753`, затем новая `feature/styleos-documents-recovery-754`.
- Макет: `StyleOS-Documents-Full-Concept.pdf`: обложка + 14 экранов.

## Что работает в host-контуре
- Данные: UTF-8, выделение, комментарии, A4/Letter, частичный DOCX экспорт.
- Контрольный импорт DOCX ZIP_STORED, включая XML и страницу. Не импортирует произвольные сжатые DOCX.
- File-token интерфейс без файловой зависимости от shell; проверена изоляция двух экземпляров.
- Представление интерфейса: окно-клиент, 8 вкладок, маршруты 14 экранов, основные текстовые события; незавершённые команды не активны.
- Подробности и фактические статусы: `docs/RECOVERY_754_RU.md`.

## Что не готово
- Полный интерфейс и настоящие функции всех 14 экранов; стабильный ABI `.tea`; независимая установка `Documents.tea`; ISO с новой версией; QEMU/VirtualBox приёмка.

## Следующее действие
- По возможности получить ранний образ, упомянутый владельцем, и искать дополнительную информацию об интерфейсе. Образ не равен исходникам.
- Возвратить архитектурный runtime Shell/Window Broker/File Broker в отдельной ветке, не касаясь 744 и `main`.
- Реализовать весь редактор по макетам, подключить приложения через `.tea`, затем тестировать ISO в QEMU, VirtualBox — отдельно.
- **Пока нет нового ISO, не заявлять готовую установочную сборку.**
