# StyleOS — принятые решения и открытые вопросы

[Точка входа](PROJECT.md) · [Все технические ADR](adr/) · [Дорожная карта](ROADMAP.md)

## Согласовано для проекта

| Решение | Практический смысл и граница |
|---|---|
| StyleOS и MATRYOSHKA — разные проекты | StyleOS идёт на реальных x86‑64/AArch64 с собственным ядром. Portable-os сохраняет M32/M8 и своё назначение. Ничего не переносим между ними автоматически. [История](HISTORY.md) |
| Общий десктоп | На ПК и телефоне с внешним монитором одна основа окон, панели задач и приложений. Мобильный экран телефона имеет свой режим. VirtualBox проверяет общий десктоп, а не физический видеовыход телефона. |
| Раздельная приёмка | Linux/QEMU, Android/Termux, VirtualBox и нативная загрузка имеют свои отчёты. PASS в одном контуре не переносим в другой. |
| Одна VM, два диска | Сменный системный носитель и отдельный постоянный диск с пользовательскими файлами и позже приложениями. Изменение системной версии не переинициализирует данные. Драйвер и формат диска ещё требуют отдельной проверки. |
| Рабочие встроенные приложения | Первый образ содержит текстовый редактор, «Файлы» и панель всех реальных процессов, системных и пользовательских. Больше полезности дают простые настоящие действия, чем заранее заполненный демонстрационный список. |
| Собственный проводник, готовые компоненты допустимы | «Файлы» работают с любым файлом как с объектом, а конкретные форматы открывают подходящие приложения. Допустимы библиотеки, порты и готовые механизмы отрисовки при подходящих требованиях и лицензии. |
| Оформление закладываем, настройку откладываем | Единые параметры цветов, шрифтов и элементов оболочки. На старте не нужен редактор тем. «Офис» позднее реагирует на события системы, но не задерживает загрузку и не скрывает ошибки. |
| SDK без собственного компилятора | Clang/LLVM/LLD, минимальный пример внешней сборки, упаковщик .tea. Первый пример — «Презентации». Исходники для другой ISA можно пересобрать, один машинный бинарник не обещаем. |
| Deep Drop — явное действие над объектом | Передаётся выбранный объект с ограниченным доступом. Перенос и восстановление проверяются отдельно от UI. Прототип на хосте не приравнивается к работающей функции в госте. |
| Обновления из файла и по сети — один механизм | Планируется вкладка «Обновления» в «Файлах». Интерфейс показывает статус, системная служба проверяет пакет и применяет его. Сначала локальный пакет и безопасный возврат, потом сеть и GitHub Releases как источник доставки. A/B — рекомендуемая схема, ещё не реализована. |
| Документы и история не удаляются | Новая точка входа живёт в GitHub, старые ветки, теги и исходные отчёты сохраняются. Ветку по умолчанию и релизы меняют отдельным решением. [Процесс](WORKFLOW.md) |

## Что не утверждено

- Окончательная модель ядра, системные вызовы и стабильный ABI приложений, общий менеджер памяти и полноценная файловая система.
- Точный контроллер диска данных, формат разметки, драйверы ввода и графики для первого рабочего образа.
- Обязательный графический toolkit, постоянная спецификация .tea, политика подписей, доверия к издателям и обновления ключей.
- Точная компоновка первого десктопа по изображению. Текстовый ориентир — меню слева внизу, открытые приложения рядом и тонкая янтарная отметка активного окна. Это не спецификация размеров и цветов.
- Перечень телефонов и периферии, способ физической установки, правила совместимости APK/EXE и даты релизов.
- Состав и дата первого публичного релиза. Перенос актуальной базы в `main` не является релизом.

## Уточнение владельца 25.11.2026

После полной приёмки ядра: Процессы, файловая система, полностью независимые приложения, экраны приветствия/входа/выбора пользователя/блокировки; затем VirtualBox. Deep Drop не забывать: перенос, изоляция и восстановление являются обязательными сквозными критериями. Интерфейс по утверждённым макетам. [План и критерии](POST_KERNEL_ROADMAP.md).
