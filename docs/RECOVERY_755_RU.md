# StyleOS «Документы» — контрольная точка 755 (бинарный клиент и брокер)

## Статус

**Выполнено:** реально собираемый самостоятельный ELF x86-64 и экспериментальный пакет `Documents.tea` со встроенным manifest.json; модель окна приложения отделена от оболочки и работает через узкий callback-контракт. Исходники, тесты и пакет можно восстановить независимо от истории чата.

**Не выполнено:** выпуск нового установочного ISO с интегрированным приложением, загрузка в StyleOS, совместимость с закрытым `styleos.system-module-v1` из 744, подпись доверенным системным ключом, восстановление полного функционала по 14 экранам. `Documents.tea` содержит `installable_in_744: false` и НЕ должен устанавливаться в 744 как официальный пакет.

## Проверено

- `tools/test_documents_755.sh`: GCC и Clang host unit/regressions; интерфейс из 754; 1200 неверных/враждебных входных DOCX; 40 воспроизводимых историй редактирования; 14 Python unit; sanitizer runtime; повторы сборки `.tea` совпадают байт-в-байт; тесты повреждения ZIP/ELF.
- В хостовом Linux-loader реально отображены PT_LOAD-сегменты x86-64 ELF и вызваны `styleos_documents_app_entry_v1`, `_event_v1`, `_draw_v1`, `_grammar_v1`; проходят ввод Unicode, сохранение и повторное открытие TXT и DOCX, отрисовка через callback. Это **не QEMU** и **не гостевая система StyleOS**, а тест машинного бинарника в отдельном Linux-процессе.
- `nm -u Documents.elf` пуст, ELF тип ET_EXEC x86-64, `Documents.tea` 26 192 байта, меньше лимита 65 536 байт. ZIP STORED содержит `manifest.json` и `payload.elf`; SHA-256 сверена.
- Контрольный ISO 744 сохраняет исходный SHA-256. Точное значение зафиксировано в `docs/744-binary-checksums.txt` и проверяется тестом аудита, не вводится вручную.

## Что действительно может приложение сейчас

- Текст UTF-8, выделение, удаление, курсор и удаление символов; базовая модель страниц A4/Letter и комментариев.
- Автономный UI client-area renderer: 8 вкладок, 14 маршрутов; действуют ввод, Backspace, новый, открытие/сохранение, Ctrl+N/O/S/P, переключение формата листа; остальные команды не следует считать реализованными.
- Сохранение TXT, создание DOCX на основе plain text и импорт собственного DOCX без сжатия. Сжатый DOCX и сложное форматирование пока отсутствуют.
- Ограниченные подсказки грамматики доступны через бинарный метод `_grammar_v1`; полный редактор рецензирования и автоформатирование отсутствуют.
- Оболочка отвечает за границы окна, фокус и выдачу токенов файлов; приложение не знает имён файлов на диске и не использует shell/global symbols.

## Предохранители

- Никакой файл контрольной 744 не менялся; пользовательский VDI не монтировался на запись.
- Рабочий стол, kernel, `main` и соседние приложения на GitHub не менялись.
- Нельзя заявлять VirtualBox, QEMU, подписание или запуск готового приложения внутри StyleOS.
- Пример `modules/runtime/freestanding.c` — автономная библиотека памяти экспериментального ELF, а НЕ системный аллокатор.

## С чего продолжать

1. Взять работающее исходное дерево 755 из ветки `feature/styleos-documents-runtime-755`, проверив SHA пакета и результаты `tools/test_documents_755.sh`.
2. Получить или воссоздать настоящее API загрузчика `.tea`, оконный менеджер, файловый брокер и сборку ISO, совместимую с возможностями 744, **без перезаписи контрольной ISO**. Старые опубликованные ветки `feature/styleos-desktop-v0` существенно старше 744 и не являются прямой заменой.
3. Добавить независимую установку/обновление приложения с проверяемой подписью, только затем интегрировать `Documents.tea` и проверять QEMU/OVMF, VirtualBox отдельно.
4. Восстановить остальные реальные команды редактора согласно `docs/IMPLEMENTATION_MATRIX_753.md` и `StyleOS-Documents-Full-Concept.pdf` (14 страниц); в том числе таблицы, картинки, ссылки, форматы, print/PDF, полноценный DOCX, правки и автоматизацию. До этого общая приёмка «Документов» невозможна.
