# StyleOS Desktop v0.6 — StyleFS v2

Отдельная ветка `feature/styleos-stylefs-v2` от v0.5 (`2305498`).
Тестовый том данных 256 МиБ. Диски v1 и старый режим заметок читаются, но
их формат не меняется автоматически. Совместное подключение нескольких томов
данных в этом рабочем столе не реализовано.

## Виртуальная машина

1. Выключить ВМ и заменить ISO на `StyleOS-Desktop-v0.6-x64.iso`.
2. Если нужно открыть прежние документы, оставить прежний VDI данных.
   Для проверки v2 отключить, **не удаляя**, прежний диск и подключить
   `StyleOS-StyleFS-v2-256MiB.vdi` в тот же слот IDE (вторичный канал,
   главное устройство, порт 1, устройство 0). Это новый пустой том.
3. В Проводнике открыть «Мой компьютер», затем диск данных. На v2 включены
   реальные размер и версия тома. `F2` — переименование, `Ctrl+C/V` — копия,
   `Ctrl+X/V` — перемещение. `Delete` и Enter удаляют выделенный файл или
   пустую папку без корзины. Escape отменяет, открытый в редакторе файл
   защищён от удаления. Существующие имена не перезаписываются.
4. На томе StyleFS редактор открывает UTF‑8 `.txt` до 64 КиБ. ФС v2 хранит и
   копирует файлы до 64 МиБ при наличии непрерывного места. Это не означает
   поддержки редактирования каждого формата или изменения лимита старых заметок.

Не нужно переразмечать ранее созданные образы. Новое ядро открывает их с прежними
лимитами формата. Для отката верните прежний ISO и, если перешли на v2, прежний VDI.
v0.5 новый v2 не читает.

## Перенос старого StyleFS на новый том

Утилита работает с raw-образами при выключенной ВМ. Она не обновляет исходный
образ, не форматирует его и не перезаписывает уже существующее имя назначения.
`migrate` переносит каталоги и данные StyleFS v1, но не VDI старого приложения
заметок до v0.4. Для утилиты подходят Linux/WSL и путь на файловой системе
хоста с поддержкой жёстких ссылок.

```sh
mkdir -p build
cc -std=c11 -O2 -Wall -Wextra -Werror -DSTYLEFS_HOST_FORMAT -Iinclude \
    tools/stylefs_image.c kernel/stylefs.c -o build/stylefs-image
qemu-img convert -f vdi -O raw /path/to/old-stylefs.vdi build/old-v1.raw
build/stylefs-image migrate build/old-v1.raw build/migrated-v2.raw 256
qemu-img convert -f raw -O vdi build/migrated-v2.raw build/migrated-v2.vdi
```

Формат описан в [ADR-0015](../../adr/0015-stylefs-v2-volume.md). Свежий тестовый
том можно создать командой `build/stylefs-image new build/data.raw 256`.
Команда `info` выводит версию и пределы образа, `put` и `get` копируют
большие файлы потоком. Утилиту не запускают поверх образа, одновременно
используемого ВМ.

## Проверки перед выпуском на железе

Нужны живой запуск с USB и доступ к накопителю целевого ПК через проверенный
контроллер, корректное распознавание своих и чужих дисков, установка на
отдельный тестовый накопитель, повторная загрузка без USB и чтение сохранённых
файлов. Нельзя из теста IDE в ВМ делать вывод о работе NVMe, USB или о сохранении
соседнего раздела Windows установщиком. Текущий ISO по-прежнему не установочный.
