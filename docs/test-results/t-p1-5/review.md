## Safety and contract audit

- Pure `op_build()` dereferences no PA and returns no page. It validates platform/source/phase, arithmetic and PA width, mandatory full-byte claims, map consistency, baseline protection and raw descriptor evidence. Failures publish `valid=0`, zero counts, zero page totals and `granted=0`.
- PROTECTED is the outward-rounded union of all baseline RESERVED and claims; nested/adjacent ranges do not count twice. REVIEW is the diagnostic candidate partition after protection subtraction, with `no-transfer`. Outside coverage remains unclassified. Every success grants zero pages.
- The only new mutable persistent storage is the 65536-byte image-owned workspace. Complete image containment and separation from stack, handoff, source, diagnostic workspace and boot-pool objects precede its first persistent write. The reused pool-layout helper is read-only; this profile does not admit, allocate or test the boot pool. Automatic C locals use the existing contained stack.
- x86 physical table reads are reached only from the actual inherited root and its descriptor children. Each whole 4096-byte table page must be baseline RESERVED and outside CANDIDATE before dereference. A bounded identity closure proves the physical access used for the visited partial set; the UEFI x64 physical-access assumption remains explicit.
- GDT VA pages are translated by the active walker; their PA pages are protected before descriptor bytes are read. No arbitrary GDT VA-to-PA cast exists. Full 4096-byte IDT bounds accept its actual 16-byte alignment and protect every touched page. IDT gates and executable image targets are checked.
- x86 raw GDT/TABLE paths are replayed without dereferencing their PAs. Every referenced table is claimed and protected; every declared table/GDT dependency has exactly one matching trace. Shared-slot translation/type/rights must agree; only hardware A/D bookkeeping differences are tolerated. The set remains explicitly partial with unresolved flags `3`.
- No new CR3/MMU, descriptor, VBAR or IRQ write path exists. x86 object inspection shows control-register reads only and no writable `.data`/`.bss` in the architecture collector or pure core. The common plan object owns exactly 65536 BSS bytes. ARM source uses system-register reads only; ARM objects similarly add only the common workspace BSS.
- ARM validates EL1h, contained aligned SP, DAIF, MMU/cache/endian-off conditions, fixed Image bounds and VBAR. `root=0` means no active stage-1 translation in this phase. Vectors and the PL011 MMIO page remain separate claims. `unresolved=0` does not authorize a transfer.

## Findings addressed during implementation

- Ownership QEMU JSON initially omitted the parsed plan; it now records phase, source data, workspace, before/after state, claims, raw paths, PROTECTED, REVIEW reasons, unresolved dependencies, totals and zero grants. Negative results explicitly record the refusal and `ownership_plan=null`.
- Initially strict shared-entry comparison could falsely reject legitimate hardware A/D updates between captures. Core and runner now tolerate only those bookkeeping bits while preserving translation/attribute consistency. Their adversarial tests cover allowed A/D differences and rejected PA/rights changes.

- GCC `-O2 -Werror` reported a possibly uninitialized local GDT range in an ARM conditional path. The main engineer initialized the local to zero. This is closed: final strict `-O2` sanitizer builds, the independent 500-plan oracle, and the fresh full suites passed with the corrected source.
