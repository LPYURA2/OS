# Независимое ревью T-P1.3

Дата: 13.11.2026. Репозиторий `/workspace/OS`, ветка `feature/styleos-t-p1-3`, принятая база `07fe425a0d4d5c0b9fbb65f8a37b30924523ec81`.

Результат статического ревью и независимых host-проверок: **PASS; открытых блокирующих замечаний нет**. Реальные QEMU и полная матрица сборки выполняются основным агентом; этот обзор не подменяет их журналами host-fixtures. Репозиторий не редактировался рецензентом; команды сборки и проверки писали только в `scratch/styleos-t-p1-3/review-host/`.

## Проверенные свойства

- API выдаёт только страницы одного image-owned массива 32768 байт. Отдельные 4096 байт метаданных никогда не выдаются. `CANDIDATE` не читается и не используется; тестовый контекст даже задаёт недопустимый счётчик кандидатов, не влияющий на допуск.
- Допуск проверяет точные размеры, оба конца полуинтервалов, сложение без переполнения, выравнивание, полный loaded-image extent и резерв всего image. Проверяются все пересечения пула/метаданных между собой, со стеком, handoff, source UEFI/DTB и всей рабочей областью.
- Карта и постоянный снимок evidence размещены в одной image-owned рабочей области. Полные адресные интервалы обоих объектов подтверждаются до чтения полей карты; массив карты ограничен `BOOT_MEMORY_INPUT_MAX`. Снимок возвращается только после успешной нормализации, передача через `boot_info` не меняется.
- До успешного допуска подсистема не пишет в пул. Отказ допуска не меняет bitmap или страницы. Предыдущая startup/loader-очистка BSS остаётся частью C-окружения и отдельно объяснена в ADR.
- Выдача обнуляет всю страницу, затем отмечает её занятой. Исчерпание, недопущенное состояние, неверный/невыровненный адрес, повторное освобождение и повторный допуск различаются. Отказы сохраняют состояние и содержимое страниц. Старый указатель после повторной выдачи не защищён от UAF; SMP не заявлен.
- Целевой самотест проверяет восемь уникальных страниц, полную первоначальную нулевую страницу, отдельные volatile-шаблоны во всех байтах, readback, исчерпание, повторную выдачу страницы №3 с нулями и сохранность остальных семи страниц. PASS печатается только после этих проверок.
- ARM-бинарный анализ проверяет размеры символов, весь writable NOBITS/PT_LOAD memory extent, VMA=LMA, BSS bounds, Image memory_size и соответствие file-backed ELF/raw-байтов. PE-анализ проверяет весь интервал каждого объекта в одной writable data section и SizeOfImage. Runtime-проверка прибавляет фактический IMAGE base к обоим RVA; preferred PE base не используется как runtime base.
- UART-classifier требует настоящего валидного префикса handoff/MEMMAP и точного порядка всех результатов до обычного HALT. Проверяет полный image/reserved/exclusion span и каждый адрес выдачи. `verified_pool_site()` заново выводит доказательство из бинарников, сверяет sidecar и хеши, включая PE disk.
- Обычный, negative-handoff, negative-map, exception и bootpool режимы разделены. Новые флаги взаимоисключающие; обычный образ не содержит самотест. Старые режимы отвергают неожиданный BOOTPOOL.
- ADR-0006 объясняет совместимые адресные пространства: поддерживаемый ARM MMU-off Image-профиль и сохранённое UEFI x64/OVMF flat/identity boot mapping. Это не общий VA→PA перевод. Общая RAM, собственные таблицы трансляции и модель ядра оставлены отдельному решению.

Сравнение с принятой базой: `boot_info` header/validator, ядро нормализации карты, collectors/parsers UEFI и DTB, ExitBootServices, ARM startup/linker, `arch/`, exception contract и `tools/fault_site.py` не изменены. Изменён только внутренний результат диагностики и защищённая рабочая область; политика нормализации сохранена.

## Замечания, исправленные до завершения ревью

1. **Alignment до разыменования evidence — закрыто.** Первоначально `e->live` читался до проверки выравнивания `e`. Проверка alignment и полного pointer extent перенесена до первого разыменования. Добавлены host-probes unaligned evidence и предельных evidence/map pointers; sanitizer проходит.
2. **PE zero-length raw tail — закрыто.** Для объекта в виртуальном BSS-хвосте `present == 0`; прежний `_range()` с offset за EOF отвергал корректный zero-fill interval. Чтение raw-байтов теперь выполняется только при ненулевом `present`; fixtures проверяют чистый виртуальный хвост и нулевой file-backed prefix.
3. **Основание совместимости адресов — закрыто.** ADR теперь явно называет узкий retained flat/identity UEFI x64/OVMF boot mapping; произвольный C-указатель не объявляется физическим адресом.

## Пределы результата

Рецензент не дублировал тяжёлые QEMU-прогоны. Основной агент должен приложить собственные фактические `--all`, ARM-only, QEMU EL1/EL2/x86 и воспроизводимость четырёх обычных артефактов. Android/Termux T-P1.3, VirtualBox и физическое оборудование этим ревью не проверены. `/map` — связанное свидетельство собственной сборки, а не аутентификация произвольного стороннего PE. Ни изменение main, ни Portable-os, ни force push, merge или release рецензент не выполнял.
