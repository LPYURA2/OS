# T-P1.3 — контрольный прогон Android/Termux

14.11.2026 (МСК). Устройство владельца, Android/Termux как хост, QEMU **11.1.3**, AArch64 `virt` через TCG. На скриншоте checkout виден короткий SHA `f10ee33`, соответствующий [закреплённому коммиту реализации `f10ee3313b7d8d428a3207e5bcfff6b93842be09`](https://github.com/LPYURA2/OS/commit/f10ee3313b7d8d428a3207e5bcfff6b93842be09). Отдельный текстовый вывод `git rev-parse HEAD` не приложен.

```sh
CC=clang python tools/test.py --host --qemu --qemu-arch aarch64 --output build/termux
```

**20/20 этапов PASS** по переданной владельцем [сводке results.json](results.json): шесть host-наборов, пять сборок ARM64 и девять запусков QEMU. Это отдельный прогон, не часть 28 этапов Linux.

| Сценарий | Итог | Наблюдение |
|---|---|---|
| [Самотест пула с начальным EL1](qemu-aarch64-bootpool.log) | PASS | `initial EL1`, `current EL1`, `BOOTPOOL PASS`, штатный halt. |
| [Самотест пула с начальным EL2](qemu-aarch64-bootpool-el2.log) | PASS | `initial EL2`, переход в `current EL1`, те же результаты самотеста. |

Оба UART-журнала показывают пул `[0x4008b000, 0x40093000)` целиком внутри зарезервированного образа `[0x40080000, 0x400a4000)`. Проверены восемь разных обнулённых страниц по 4096 байт, чтение и запись, отказ при исчерпании и повторная выдача обнулённой страницы `0x4008e000`. SIGTERM отправлен тестовым скриптом после `KERNEL HALT`, не из-за ошибки. Выдачи из `MEMMAP CANDIDATE` нет.

Приложены сводка и два журнала, переданные текстом, с окончаниями строк в формате чата. Остальные журналы, версии Python/Clang/LLD и файлы проверки расположения пула с устройства не приложены. Сценарии исключений имеют PASS в сводке, но их исходные UART-журналы здесь не дублируются. Вставка двух склеенных команд `cat`/Git выдала ошибку уже при извлечении журналов и не относится к запуску тестов.

Этот результат не проверяет x86-64 QEMU или воспроизводимость в Termux, VirtualBox, нативную загрузку устройства или общий аллокатор RAM. [Основной отчёт T-P1.3](../README.md).
