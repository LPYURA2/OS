# Deep Drop v0 — первый рубеж

База ветки `feature/styleos-deep-drop-v0` — `main` на
`932713149c5b4d4541c6ec60120c3141b7a78e1c`. SDK не влит в ветку.
Для стенда отдельно использован SDK на `f1893b7ac932be2d079392e99094954c46029a08`.

## Что работает

- [Контракт](../../../include/styleos/deep_drop.h) описывает выбранные данные
  как тип и байты, а цель — как список принимаемых типов и пару операций.
- [Общий модуль](../../../kernel/deep_drop.c) проверяет тип и размер, предлагает
  получателю подготовить результат во временном буфере и только после проверки
  результата вызывает его применение. В модуле нет знания о файлах,
  «Презентациях», жестах или SDK. Он не включён в образы ОС.
- [Стенд](../../../tests/test_deep_drop.c) подаёт выделенный текст и содержимое
  реального временного `.txt` одинаковым способом. Он вызывает оригинальную
  C-функцию `styleos_app_text_v0`, скомпилированную для хоста, и проверяет
  состояние тестового слайда. Путь файла не передаётся получателю. Другой
  тестовый получатель принимает бинарные байты через тот же контракт.

На этом рубеже подготовка и применение выполняются синхронно в одном
процессе. Предполагаются доверенные тестовые обработчики, а раздельные буферы
не являются изоляцией памяти или прав. Возврат ошибки обработчиком проверен,
реальное падение процесса и восстановление пока нет.

## Повтор проверки

Из корня checkout ветки, при наличии Python 3 и компилятора C11:

```sh
git fetch origin f1893b7ac932be2d079392e99094954c46029a08
git worktree add --detach ../styleos-sdk-fixture f1893b7ac932be2d079392e99094954c46029a08
python3 tools/test_deep_drop.py --sdk-dir ../styleos-sdk-fixture/sdk
python3 tools/test.py --all --output build/deep-drop-regression
```

Первая команда тестов использует `CC` или `cc`, не требует QEMU, не запускает
`.tea` и не оставляет бинарники в репозитории. Для полной регрессии нужны
инструменты из [инструкции по сборке](../../QUICKSTART.md).

| Проверка | Результат |
|---|---|
| Deep Drop, Linux x86‑64, GCC 14.2.0 и Clang 19.1.7 | 9/9 PASS каждым компилятором |
| Повтор стенда с GCC UndefinedBehaviorSanitizer | 9/9 PASS |
| `tools/test.py --all`, QEMU 10.0.13 для x86‑64 и AArch64, Python 3.12.14 | 57/57 PASS, включая проход 299 существующих Python-тестов |
| Обычный `BOOTX64.EFI`, `styleos.img`, AArch64 `kernel.elf` и `styleos.bin` | 4/4 побайтно совпали с заново собранным `main` на той же цепочке инструментов |
| Перезапуск обработчика, гостевой Deep Drop, VirtualBox и Termux | Не проверены на этом рубеже |

## Следующий рубеж

Вынести подготовку результата в отдельный процесс на стенде и уронить его
после получения данных, но до применения. Проверить сохранность исходника
и слайда, перезапуск только обработчика и одно применение при повторе.
В госте оболочка позже передаст этому механизму выбранную цель и данные.
Рабочий стол, установка `.tea` и первый жест мышью остаются отдельными
рубежами [дорожной карты](../../ROADMAP.md). Свёрнутые окна, создание заметок
из выделения и передача фото не входят в реализацию этого рубежа.
