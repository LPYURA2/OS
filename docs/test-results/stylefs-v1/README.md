# StyleOS Desktop v0.4 — первый StyleFS

База — `6b26407`, загрузочный ISO Desktop v0.3. Ветка `feature/styleos-filesystem-v1`.
Носитель системы и тестовый диск данных независимы.

## Первые действия в VirtualBox

1. Полностью выключить ВМ. Подключить `StyleOS-Desktop-v0.4-x64.iso` вместо
   предыдущего ISO к виртуальному CD/DVD. Оставить UEFI, VMSVGA и PS/2 Mouse.
2. Для теста StyleFS временно **отключить, не удаляя** `StyleOS-Data.vdi`, и
   вместо него подключить **`StyleOS-StyleFS-Test.vdi`** на втором канале IDE,
   главное устройство (порт 1, устройство 0). Не подключать оба образа
   к одному слоту и не переразмечать старый диск.
3. Запустить ВМ. В «Файлах» появятся папки «Документы», «Проекты», «Загрузки»,
   «Музыка», «Изображения» и «Видео». Кнопка `+ Папка` создаёт каталог. Выделить
   строку щелчком и открыть через Enter или «Открыть». Кнопка `..` поднимает
   на уровень выше.
4. Внутри папки нажать `+ Текст`, ввести текст и нажать Ctrl+S. Вернуться
   в «Файлы» по F2, выбрать файл `Текст.txt` и переименовать по F2. Ctrl+C
   и Ctrl+V копируют выделенный файл в другой каталог, не перезаписывая
   одноимённый файл. Стрелки и PgUp/PgDn позволяют прокручивать список.
5. Перезагрузить ВМ и открыть сохранённый текст. Чтобы снова работать со
   старыми заметками, выключить ВМ и вернуть прежний `StyleOS-Data.vdi`.

Редактор в этом этапе открывает UTF‑8 `.txt` до 4096 байт. ФС умеет хранить и
копировать любые байты до 64 КиБ на файл, но наличие файла на диске не означает
умения отредактировать его формат. Например, `.docx` можно скопировать, пока
редактор Word-формата ещё не реализован. Удаление и перемещение реализованы
и протестированы в ядре ФС и утилите образов, но не вынесены в интерфейс
«Файлов» на этом этапе. Нативная флешка и установщик ОС не входят в сборку.

## Сборка

См. [описание формата](../../adr/0014-stylefs-v1-experiment.md). Утилита
образов рассчитана на Linux/WSL и работает с файлами raw, не VDI и не
физическими дисками. Не подключайте один образ к гостю одновременно с
изменением этого же образа на хосте.

```sh
mkdir -p build
cc -std=c11 -O2 -Wall -Wextra -Werror -DSTYLEFS_HOST_FORMAT -Iinclude \
   tools/stylefs_image.c kernel/stylefs.c -o build/stylefs-image
build/stylefs-image new build/stylefs.raw
qemu-img convert -f raw -O vdi build/stylefs.raw build/StyleOS-StyleFS-Test.vdi
python3 tools/build.py --arch x86_64 --desktop-v0 --output build/v04
python3 tools/make_desktop_iso.py --efi build/v04/x86_64/BOOTX64.EFI \
    --output build/StyleOS-Desktop-v0.4-x64.iso
cc -std=c11 -Wall -Wextra -Werror -DSTYLEFS_HOST_FORMAT -Iinclude \
    tests/test_stylefs.c kernel/stylefs.c -o build/test-stylefs
build/test-stylefs
python3 tools/test_stylefs_desktop.py --boot build/StyleOS-Desktop-v0.4-x64.iso \
    --data-template build/StyleOS-StyleFS-Test.vdi --image-tool build/stylefs-image \
    --output build/stylefs-proof
python3 tools/test.py --all --output build/stylefs-regressions
```

## Результаты

| Проверка | Результат |
|---|---|
| Загрузка x86-64 UEFI с итогового ISO и подключение StyleFS VDI | PASS в QEMU/OVMF |
| Новая вложенная папка, запись UTF‑8 текста, переименование и открытие после перезагрузки через «Файлы» | PASS в QEMU |
| Копирование незнакомого `.docx` через UI, идентичность исходника и копии по байтам | PASS в QEMU, редактор `.docx` не задействован |
| Курсор, отсутствие записи на повреждённый том того же размера, неизменность ISO и чистого шаблона VDI | PASS в QEMU |
| Старый VDI с заметками, загрузка без диска данных, старый курсорный тест, повторное чтение старого формата после отката к прежнему образу | PASS в QEMU |
| Проверки ФС на хосте с ASan и UBSan | PASS, в том числе обрывы в 16 точках записи/flush многосекторного файла, обрыв заголовка, восстановление при повреждении новой копии |
| Две сборки ISO и два сырых чистых тома | Побайтно совпали |
| Штатные x86-64 и AArch64 сборки и проверки | 57/57 PASS, четыре обычных артефакта совпали с базой v0.3 |
| Компиляция ядра StyleFS для AArch64 | PASS. Подключение ФС в ARM-гостя не проверялось |
| Тест v0.4 в VirtualBox, на физическом ПК и OnePlus | Не запускался |
