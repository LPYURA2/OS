# StyleOS v0.7 — гостевой системный диск и обновление из файла

Ветка `feature/styleos-offline-update-v1` от v0.6 (`81a9e2e`).
Профиль x86-64 UEFI с постоянным системным диском подходит для тестов в ВМ.
Он загружается без ISO. Формат диска данных StyleFS не менялся.

## Проверка в VirtualBox

1. Разархивируйте сборку в отдельную папку. Выключите тестовую ВМ и сохраните
   прежний ISO и VDI данных. Для первой проверки удобнее отдельная ВМ.
2. Включите EFI (без Secure Boot), выберите клавиатуру и мышь PS/2,
   контроллер IDE PIIX3, один vCPU, 512 МиБ или больше. Отсоедините ISO.
3. Подключите `StyleOS-System.vdi` как IDE Primary Master
   (первичный канал, порт 0, устройство 0). Подключите
   `StyleOS-Test-Data.vdi` как IDE Secondary Master
   (вторичный канал, порт 1, устройство 0). Для системного VDI нужен обычный
   режим диска с сохранением изменений. Не выбирайте неизменяемый диск.
4. Запустите ВМ. В Проводнике нажмите «Обновления» или «Загрузки»,
   выделите `Build-701.supdate` и нажмите Enter, затем Enter для подтверждения.
   Escape отменяет. После сообщения о готовности сохраните открытый текст
   и нажмите «Перезагрузка» в меню StyleOS.
5. После загрузки в «О системе» и разделе «Обновления» ожидается «Сборка 701».
   Она должна остаться и после полного выключения ВМ. При зависании до
   появления рабочего стола нажмите Reset в VirtualBox один раз. Загрузчик
   увидит, что пробный запуск не подтверждён, и вернётся к прежней сборке.

Тестовый том данных уже содержит пакет в «Загрузках». На другое время можно
подключить свой ранее созданный StyleFS VDI на его место. Система не
копирует пакет в существующий том и не форматирует его. Отдельный файл
`Build-701.supdate` в архиве не нужно подключать как виртуальный диск или ISO.
Для переноса на свой том можно использовать существующий `stylefs-image put`
на raw-копии VDI при выключенной ВМ. Общих папок VirtualBox здесь пока нет.

## Как устроено обновление

- Системный диск имеет неизменяемую средствами обновления ESP с проверенной
  базовой сборкой. В системе неподписанный или изменённый пакет отвергается.
  Для проверки используется Ed25519 из Monocypher. SHA-512 связывает подпись
  с точными байтами новой сборки. Это механизм StyleOS, не UEFI Secure Boot.
- Пакет записывается в неактивный слот, сбрасывается на диск и повторно
  проверяется. Две чередующиеся записи с номером поколения и CRC хранят
  состояние. Активный слот и ESP при подготовке не перезаписываются.
- До запуска новой версии загрузчик отмечает пробную загрузку. Она
  подтверждается после первого кадра рабочего стола и готовности
  клавиатуры/мыши. Это начальный критерий, он не проверяет все драйверы или
  приложения. Если пробная сборка вернулась с ошибкой из загрузчика, откат
  происходит в той же загрузке. При зависании нужен ручной Reset.
- Текущий профиль работает только с выделенным системным образом 68 МиБ на
  первичном IDE master c ожидаемой сигнатурой. Нет установки на физический ПК,
  онлайновых обновлений, NVMe, Secure Boot, ротации ключей и установки `.tea`.
  Пакет этой демонстрации подписан тестовым ключом. Постоянный ключ релизов
  и схема его смены ещё не настроены.

## Где смотреть код

- `kernel/system_update.c` — подпись пакета, слоты и записи состояния.
- `boot/x86_64/desktop_update.c` — выбор сборки, запуск через UEFI и отметка готовности.
- `kernel/desktop_stylefs.c` — выбор файла и подтверждение в Проводнике.
- `arch/x86_64/desktop_io.c` — два независимых канала IDE.
- `tools/system_update.py` — создание системного образа, формат упаковки,
  подпись ключом Ed25519 через OpenSSL. Параметры `--update-build` и
  `--update-public-key` в `tools/build.py` включают отдельный профиль.
- `tools/test_system_update.py` — тест живой ВМ через QMP, PS/2 и запись
  в реальные виртуальные диски. Обычные образы не содержат этого кода.

## Файлы и документы

StyleFS хранит содержимое файлов независимо от расширения. В частности
`.docx`, `.doc` и `.pptx` можно хранить и копировать как обычные файлы,
если они вписываются в лимиты тома. Побайтное совпадение исходного и
скопированного DOCX покрыто тестом. Текстовый редактор читает и сохраняет
UTF-8 `.txt` до 64 КиБ. Приложение «Документы» и чтение Word здесь пока не
реализованы. Разумный первый этап для «Документов» — просмотр `.docx` без
изменения исходника. Старый бинарный `.doc` и презентации — отдельные форматы.

## Результаты

- QEMU/OVMF: загрузка 700 без ISO, отмена пакета и отказ при изменённой
  подписи, переход 700 → 701, отказ повторной установки 701, неудачная
  пробная загрузка 702 → откат на 701. Повторное включение с тем же VDI
  загрузило 701. ESP и отдельный диск данных остались побайтно неизменны.
- Основные проверки x86-64 и AArch64: 57/57 PASS. Четыре обычных артефакта
  сборки побайтно совпали с v0.6.
- Профиль прежнего Desktop без обновления повторно прошёл тест с ISO:
  StyleFS v2, просмотр диска, копирование DOCX, Deep Drop, создание, запись и
  повторное открытие текста после перезагрузки.
- VirtualBox и физическое железо в этом этапе не проверялись.
