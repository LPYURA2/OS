# T-P1.8B independent safety audit

Result: **no blocking safety defect found** in the reviewed guest loader, read-only storage integration, finite AArch64 roots, or full exception/dispatcher return path. This is a source and sanitizer audit, not an additional VM result.

Scope: read-only inspection of `/workspace/OS` at the source hashes in `safety-audit.json`. Read task T-P1.8B, AGENTS.md, ADR-0010/0011/0012 and the new loader/demo/architecture headers and code, plus the existing VirtIO/storage code needed to assess their use. No repository edits, Git commands, remote operations, or QEMU were performed. Scratch host binaries were written only under `safety-tests/`.

## Audited properties

- **Admission precedes new mutable writes.** `kernel/disk_app_demo.c:91-148` proves the complete finite table/control/entry-stack/code/user-stack/storage-workspace/VirtIO buffer intervals, image reservation, alignment, arithmetic through `bm_extent`, mutual exclusions, and exclusions from live stack/handoff/DTB/diagnostic/pool/metadata/vectors. This precedes `vb_open` and `st_mount` at lines 280-291. The call to `boot_pool_check_layout` is read-only and does not admit or allocate the boot pool.
- **Read-only I/O and retirement.** The only adapters used by mount/read reject WRITE and FLUSH (`kernel/disk_app_demo.c:169-178`). Every transport read uses the existing one-outstanding completion path, which validates used index/id/length/status and configuration before success (`arch/aarch64/virtio_block.c:252-293`). `drain` closes reads, barriers, checks `requests == reads == avail.idx == used.idx`, bounded nonzero request count, zero writes/flushes/denials, and stable raw indices (`kernel/disk_app_demo.c:186-205`). All later paths use saved state; none calls transport getters/MMIO/request/reset, and VirtIO MMIO is absent from both new roots.
- **I/O/refusal cannot execute fallback code.** Any transport/store failure halts. After a successful read and drain, loader rejection either halts or returns the requested reject result before copy/prepare/EL0. A valid file in the reject scenario also halts. There is no built-in alternate executable; assembly contains trusted entry/vector glue only.
- **Complete validation before publication/copy.** `kernel/disk_app.c:21-72` bounds the complete 32-byte-header/28-byte-code file, checks magic/version/ISA/reserved/entry/length/checksum, and validates all seven A64 words. Only the marker and exit immediates vary. Pointer arithmetic, destination capacity/alignment, and all source/destination/info overlaps are checked before output changes. Header fields never select VA or PA.
- **Instruction visibility.** Copying and table construction occur with M/C/I off. `arch/aarch64/disk_app.c:234-268` performs `DSB SY; IC IALLU; DSB SY; ISB` after code copy and before executable mapping; translation activation uses barriers and TLB invalidation. The activated regime leaves caches off with Normal-NC image/user memory and Device-nGnRnE UART.
- **Finite hardware mapping closure.** `arch/aarch64/disk_app.c:94-174,244-275` constructs two finite roots and recursively verifies every reachable descriptor, exact attributes, absent extra leaves, no blocks/loops/table aliases, and zero unused table reserve. SAFE has zero user leaves. APP has exactly the dedicated RX code page and RW/NX stack. Identity kernel/image aliases remain privileged with UXN; UART is privileged NX. The known fault VA `0x12010000` is absent at L2, matching ESR `0x92000006`.
- **Full lower-EL trap frames and origin.** `arch/aarch64/disk_app_entry.S:57-93` saves X0-X30 before clobbering scratch registers and records SP_EL0/ELR/SPSR/ESR/FAR/TTBR0/trusted frame SP/vector. `da_arm_capture` requires the exact trusted 320-byte frame, lower-EL vector 8, EL0t/masked PSTATE, expected user SP and APP root, and exact fault or SVC proof (`arch/aarch64/disk_app.c:309-340`). Current-EL synchronous exceptions go to terminal early diagnostics (`disk_app_entry.S:112-123`).
- **SAFE and original dispatcher stack before release.** Capture switches to SAFE and checks readback. Assembly restores the saved original dispatcher SP before `da_arm_finish`; finish checks SAFE plus original live-stack containment before clearing active/context/dispatcher pointers (`disk_app_entry.S:94-110`; `arch/aarch64/disk_app.c:343-352`). The original AAPCS64 nonvolatile register frame is then restored.
- **Fresh reentry, never stale-fault resume.** The guest checks released SAFE state, clears the user stack and full context/event, reinstates initial PC/SP/PSTATE, and sets X0=0 then X0=1 (`kernel/disk_app_demo.c:215-265`). Each invocation executes a fresh `ERET`; after fault there is no exception `ERET` back to the fault PC. `da_arch_run` accepts initial PC only. The second run must return the disk payload's X19 marker and X0 exit result through exact SVC #2.

## Host verification

GCC 14.2.0 (Debian 14.2.0-19), `-std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined -fno-omit-frame-pointer -g`:

- `tests/test_disk_app.c + kernel/disk_app.c`: PASS, 3 groups (header/bounds, every bit of all seven opcodes, atomic copy/arguments); no ASan/UBSan diagnostic.
- `tests/test_disk_app_fdt.c + boot/aarch64/disk_app_fdt.c`: PASS (scenarios, fixed MMIO, malformed bounds/profile, unchanged refusals); no ASan/UBSan diagnostic.

The toolchain environment was sourced from `/workspace/scratch/styleos-toolchain/env.sh`. Its Clang sanitizer attempt could not link because its packaged `libclang_rt.asan_static.a`/`libclang_rt.asan.a` are absent. The same checks were therefore compiled and run with system GCC successfully. This tooling limitation is not a code failure.

## Limits and integration follow-through

No VM, ELF/Image decoding, baseline byte comparison, or SHA binding of live UART was performed by this independent audit. Integration must retain its actual VM/frame/table/disk-SHA proofs and confirm all existing storage/VirtIO files and old artifacts are unchanged against base `1ea8d090cd12c4a5d20f628c927fcba787aede98`. This audit recorded current hashes of existing storage/VirtIO sources but intentionally used no Git comparison. The reviewed retirement proof assumes the supported QEMU VirtIO device obeys completion semantics; it does not claim protection against a malicious DMA device, IRQ/SMP concurrency, or physical durability.
