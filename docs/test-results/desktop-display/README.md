# StyleOS — графическая контрольная сборка x86-64

Проверен отдельный профиль `--test-desktop-display`. База сравнения —
`40c3987d4b78e0f67888db8d6baa24c7af4a35d0`. Clang/LLD 19.1.7,
QEMU 10.0.13, x86 OVMF 2025.02. Контрольные гостевые логи хранятся рядом.

| Проверка | Фактический результат |
|---|---|
| Хостовая проверка границ, RGB/BGR и защиты padding | PASS |
| x86-64 QEMU с VGA | PASS: настоящие пиксели гостя 1280×800, COM1 DISPLAY PASS |
| Тот же образ без видеоустройства | PASS: ожидаемый отказ, COM1 и штатный halt сохранены |
| Оба подготовленных VDI на SATA в QEMU/OVMF | 2/2 PASS, не VirtualBox |
| Повторная сборка графического образа | 2/2 артефактов идентичны |
| Полный прежний Linux/QEMU-набор на базе и с изменением | 57/57 PASS в каждом, обе архитектуры |
| Python unittest с изменением | 299/299 PASS |
| Прежние загрузочные бинарники и образы, включая storage и disk-app | 48/48 идентичны базе |
| Повтор T-P1.8B на AArch64 QEMU под Linux | 16/16 PASS |
| Новый VirtualBox, Termux или нативный телефон | Не запускались в этой проверке |

В положительном тесте QEMU снимает экран **после** маркеров ExitBootServices,
HANDOFF PASS, MEMMAP PASS и DISPLAY PASS. Проверяются значения пикселей
фона, нижней панели, разделителя и янтарного штриха. Скриншот не заменяет эти проверки.
Отрицательный тест использует тот же системный образ и не подключает VGA.

## Воспроизведение

```sh
python3 tools/test_desktop_display.py --output build/desktop-display-proof
python3 tools/test.py --all --output build/desktop-regression
python3 tools/test_disk_app.py --output build/desktop-arm-disk-regression
```

Для графического runner нужны QEMU x86-64, OVMF CODE/VARS и стандартный VGA ROM
дистрибутива QEMU. Если инструменты извлечены в пользовательский каталог,
можно задать `QEMU_X86`, `OVMF_CODE`, `OVMF_VARS` и `QEMU_DATA_DIR`.
Каталог вывода первого runner должен быть новым.

На VirtualBox сначала проверяют обычный системный VDI по COM1, затем на той же
VM меняют системный диск на тестовый графический VDI. Эту сборку нельзя принимать
как первую рабочую оболочку: в ней нет ввода, хранения пользовательских
файлов или приложений. Диск пользователя пока подключать не нужно.
