# Desktop v0.1 — локальная отрисовка курсора

База — первый интерактивный образ `e9dee2926a7fbc243d6c3a9e37197febaafcf3b4`.
Пользователь запустил его в VirtualBox. На видео окно VM оставалось на месте,
но в движении мыши внутри гостя были видны промежуточные стадии отрисовки.
Ранее курсор менял координаты и инициировал перерисовку всей сцены напрямую
в видимый GOP framebuffer. Неподвижный кадр отображался нормально.

## Подход

Используем обычные *damage regions*. При спокойном движении мыши помечаются
только предыдущее и новое положение программного курсора, до двух областей
по 10×17 пикселей. При переходе между элементами добавляются старые и новые
области подсветки. При перемещении окна пересчитываются его старое и новое
положение, а не весь экран. Без события или обновления часов записи нет.

Каждая изменённая область собирается в оперативной памяти полосами до 32
строк и пересылается в framebuffer только после отрисовки всех её слоёв.
Промежуточную заливку фона не выводим. Это не аппаратный курсор и не
переключение целого кадра по VSync. Все компоненты остаются в отдельном
профиле Desktop v0. Формат данных, драйвер IDE и файлы пользователя не менялись.

[Windows DXGI и обновлённые прямоугольники](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api) · [wlroots и программный курсор в областях обновления](https://wlroots-mcoffin-1cdac29cb2c88d18344d3428ac7c6eebf768973cc4a651d.pages.freedesktop.org/wlr/types/wlr_output.h.html)

## Повтор проверки

```sh
mkdir -p build
cc -std=c11 -Wall -Wextra -Werror -pedantic -Iinclude tests/test_desktop_damage.c \
    kernel/desktop_draw.c -o build/test-desktop-damage
build/test-desktop-damage
python3 tools/test_desktop_v0.py --output build/cursor-proof
python3 tools/test.py --all --output build/cursor-regression
```

Хостовый тест проверяет отсутствие записи при бездействии, ровно 340 записей
пикселей для двух раздельных областей курсора, сохранность остальных пикселей
и смещения строки, а также то, что видимая память не затронута до завершения
компоновки каждой полосы. Прогон QEMU использует реальную мышь PS/2 и сверяет
кадры попиксельно. При уходе со строки очищается подсветка, указатель не
оставляет следов, а исходный кадр восстанавливается полностью.

| Проверка | Результат |
|---|---|
| Хостовый тест отрисовки | 4/4 PASS, в том числе с UBSan |
| Поставляемый системный VDI и копия прежнего VDI данных в Linux/QEMU 10.0.13 | PASS. 1280×800, локальная отрисовка курсора и подсветки, перемещение и управление окнами, сохранение, перезагрузка, повторное открытие заметки |
| Обычные регрессии x86‑64/AArch64 | 57/57 PASS |
| Четыре стандартных загрузочных артефакта x86‑64/AArch64 | Побайтно совпали с предыдущей проверенной сборкой |
| Повтор мерцания в VirtualBox с исправленным VDI | Ожидается запуск владельца. Старый запуск подтверждает саму загрузку, но не проверку этого исправления |

Для замены образа полностью выключите ВМ. На IDE Primary Master подставьте
`StyleOS-System-Cursor.vdi` вместо старого `StyleOS-System.vdi`. Не меняйте
`StyleOS-Data.vdi` на IDE Secondary Master. Запустите ту же ВМ и повторите
движение курсора по рабочему столу и перетаскивание окна «Файлы».
