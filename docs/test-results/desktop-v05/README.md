# StyleOS Desktop v0.5 — первый перенос макетов

База — `4e85654` (v0.4, StyleFS). Ветка `feature/styleos-desktop-v0-5`.
Формат тома, параметры IDE, данные и механика запуска остались прежними.

## Что заметно в рабочей системе

- При подключённом StyleFS «Файлы» называются «Проводник». Есть быстрый доступ,
  навигация назад/вперёд/вверх, путь, список, «Мой компьютер» и раздел внешних
  устройств. Показан реальный доступный том данных. Загрузочный ISO не подменён
  фиктивным диском. «Поиск в папке» и «Обновления» пока неактивны.
- Обычные `.txt` открывает «Текстовый редактор» с кнопками «Новый», «Открыть»,
  «Сохранить», вкладкой текущего файла и отметкой несохранённых изменений.
  `Открыть` и `Ctrl+O` переводят в Проводник. Одна вкладка, UTF‑8, прежний
  лимит редактора — 4096 байт. Открытие другого файла не уничтожает несохранённый текст.
- Оригинальные шесть иконок добавлены как ресурсы. В новом режиме используются
  иконки Проводника, Редактора и Процессов. Иконки Заметок, Настроек и Документов
  подготовлены для переноса их собственных экранов. Старый VDI с заметками
  сохраняет прежний вид и способ открытия заметок.
- Новый вид Заметок, Документов и таблицы Процессов в этот шаг не входит.
  «Процессы» пока показывает открытые окна, не PID или память процессов.

## Как попробовать Deep Drop

1. Запустить ISO x86-64 UEFI вместо предыдущего ISO. Не менять подключённый
   диск `StyleOS-StyleFS-Test.vdi` v0.4 (IDE порт 1, устройство 0).
2. Открыть Текстовый редактор и создать или открыть документ назначения.
   Для удобства свернуть редактор, оставив его кнопку на панели задач.
3. В Проводнике открыть папку с другим небольшим UTF‑8 `.txt`. Зажать мышь
   на строке файла, перетащить на кнопку «Редактор» панели задач и отпустить.
   Цель подсветится, редактор восстановится, содержимое файла появится у каретки.
   Если рабочая область редактора видна, отпустить можно и над ней.
4. Исходник остаётся на месте. Текст в редакторе считается изменённым, но
   записывается на диск только по сохранению. Отпускание вне цели и Escape
   отменяют перенос. Исходник не вставляется в себя. При недостающем месте
   операция целиком отклоняется, без частичной вставки.

Это локальная операция внутри оболочки для текста с диска StyleFS. Обмен
между отдельными приложениями и остановка/перезапуск обработчика при его
сбое — отдельные следующие шаги. Поддержки двоичных вставок и папок нет.

## Повторяемость

Растровая таблица для сборки уже включена в исходники. Если исходные PNG
поменяются, её можно собрать в Python с Pillow:

```sh
python3 tools/pack_desktop_icons.py --source assets/desktop/icons --output kernel/desktop_app_icons.inc
```

Остальная сборка не требует Pillow. Тест через QEMU, после подготовки ISO
и хостовой утилиты образов из инструкции v0.4:

```sh
python3 tools/test_stylefs_desktop.py \
  --boot build/StyleOS-Desktop-v0.5-x64.iso --data-template /path/to/StyleOS-StyleFS-Test.vdi \
  --image-tool /path/to/stylefs-image --output build/desktop-v05-proof
```
