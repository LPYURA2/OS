# Проверка восстановления исходников 709

Ветка: `restore/styleos-709-repro-ci`, исходное дерево взято из `f81631d980824f2338ae68eaca0a7c549cc8161f`.

На отдельном GitHub Actions runner собирается настоящий `BOOTX64.EFI` из восстановленных C/ASM исходников и упаковывается в `StyleOS-709-Recovered.iso`. После упаковки запускаются хостовые регрессии и попытка сквозной проверки ISO в QEMU/OVMF.

**Важные границы:** этот профиль использует `--desktop-v0`, то есть его ISO не является точной побайтовой копией оригинального подписанного `Build-709.supdate`. Проверка QEMU и регрессий осуществляется в CI, при ошибках они не меняют исходники. Фактический результат каждого прогона нужно читать в журнале Actions; наличие workflow и ISO в артефактах само по себе не доказывает PASS.

Образы StyleOS 730 и 744, ветки `main`, `restore/styleos-source-705-to-709`, а также пользовательские диски данных не изменяются.

Команды:
```sh
python3 tools/build.py --arch x86_64 --desktop-v0 --output build/recovery-709/compiler
python3 tools/make_desktop_iso.py --efi build/recovery-709/compiler/x86_64/BOOTX64.EFI --output build/recovery-709/StyleOS-709-Recovered.iso
python3 tools/test_desktop_v0.py --boot build/recovery-709/StyleOS-709-Recovered.iso --output build/recovery-709/qemu-check
```
