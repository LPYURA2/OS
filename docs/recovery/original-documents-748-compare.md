# StyleOS 748 — сравнение текста в «Документах»

Внутренний этап над 747 (`3c6a320`), ветка
`feature/styleos-documents-compare`. Это команда «Сравнить» из
утверждённой вкладки «Проверка». Остальная оболочка, палитры и main
не менялись.

## Сценарий

1. В открытом редактируемом документе нажать «Проверка» →
   «Сравнить» и выбрать исходный DOCX или TXT.
2. Просмотреть список различий. Знаком «−» обозначена строка только
   из выбранного файла, «+» — строка только из открытого документа.
   Номер относится к одной из двух версий. Совпадающие строки не
   показываются. Длинные строки переносятся, список прокручивается.
3. Закрыть результат кнопкой или Esc. Источник не становится
   открытым документом. Текущий черновик и файлы на диске не меняются.

Для DOCX редактор проецирует обе версии на один и тот же текст
основной части WordprocessingML. Выбранный DOCX разбирается в
процессе «Документов», без установки на место текущего файла.
Разница считается по наибольшей общей последовательности строк.
CRLF и LF равнозначны. Одинаковый хеш не заменяет сравнение байтов.

## Границы

До 128 строк и 8 КиБ текста на документ. Это **построчное
сравнение текста**, не проверка стилей, структуры таблиц, картинок,
колонтитулов и комментариев. Команда не включает отслеживание правок
и не создаёт третий документ. DOCX должен читаться существующим
движком. Орфография, грамматика, язык проверки, отслеживание правок
и «Автоматизация» остаются отдельными задачами. «Отправить в заметки»
не входит в этот этап и остаётся в идеях.

## Проверки

- [Сценарий в QEMU](compare.json) прошёл после чистой установки.
  Внешний DOCX с кириллицей дал ожидаемые добавленные и удалённые
  строки, TXT с CRLF оказался равен черновику. Проверены прокрутка
  через три экрана, отказ от повреждённого DOCX и длинного по числу
  строк TXT, отмена выбора. Сохранённый после сравнения активный
  DOCX содержал исходный черновик. Пять файлов сравнения остались
  побайтно неизменными.
- В том же образе прошли [комментарии](comments.json),
  [разрывы и колонтитулы](page_controls.json), [PDF](pdf.json)
  и [сохранение](save.json). Проверен парсер ZIP/ELF пакета .tea.
- Базовая матрица x86-64/AArch64 — 57/57 PASS. Повторная сборка
  воспроизвела ISO, BOOTX64.EFI и Documents.tea
  ([SHA-256](repro.sha256)).

## Воспроизведение

```sh
python3 tools/test_documents_compare.py --iso <StyleOS-Install-x64.iso> \
  --image-tool <stylefs-image> --output <new-test-dir>

cc -std=c11 -Wall -Wextra -Werror -I include \
  tools/test_documents_compare_host.c kernel/documents_compare.c \
  -o /tmp/styleos-documents-compare
/tmp/styleos-documents-compare
```

Требуются QEMU/OVMF и python-docx. Хостовый тест проверяет кириллицу,
повторы и вставки между совпадениями, пустые строки, переносы,
ровно 128 строк и корректный отказ от превышения. VirtualBox не
запускался. Общая приёмка «Документов» ещё впереди.
