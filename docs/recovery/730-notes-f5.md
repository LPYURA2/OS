# Восстановление 730: отдельные «Заметки» через F5

Источник базового кода: восстановленный от оригинальных патчей код 709, ветка `restore/styleos-source-705-to-709`, продолжение от проверенного `98d167d58427f4c21937064a2dc1bb434797b870`.

Поведенческий эталон: `StyleOS-730-Test.zip` (`START.txt`) — F5 «Заметки», F3 «Текстовый редактор», F8 список PID, F10 пересоздание оболочки с сохранением PID и несохранённого текста. Оригинальный архив 730 не изменялся.

## Реализация

- «Заметки» (`NOTE_WINDOW`) и «Текстовый редактор» (`NOTES` в историческом коде) — два разных окна и независимые PID в реестре сеансов. Через F5 и F3 их можно открыть одновременно.
- Каждый редактор хранит **отдельный** буфер UTF-8, идентификатор файла, каталог, курсор, прокрутку, dirty и статус в `kernel/desktop_sessions.c`, а не в модуле оболочки.
- Рендерер выбирает черновик по конкретному окну, а не по последнему активному приложению. Открытые окна не смешивают содержимое при перерисовке.
- F10 уничтожает и пересоздаёт только компоновку окон, сохраняет оба черновика, PID приложений и выбранные файлы.
- Ctrl+N/Ctrl+S действуют на активный редактор. Сохранённые заметки на StyleFS v2 получают имена `Заметка.txt`, `Заметка 2.txt` и так далее, текстовые документы — `Текст.txt` и далее. Открытие файла «Заметка*.txt» из Проводника запускает «Заметки».
- Нельзя перезагрузить или закрыть окно с несохранённым текстом без предупреждения. Отказ при недоступном диске не сбрасывает черновик.

## Проверки

Host: `python3 tools/test_desktop_sessions.py` (отдельные PID/черновики, F10, предел PID). UEFI x86-64: `python3 tools/build.py --arch x86_64 --desktop-v0 --output build/...`.

QEMU: `python3 tools/test_730_notes_f5.py --iso ... --output ...` — отдельные видимые строки в F3 и F5 до F10, одинаковые пиксели каждого черновика после F10, 4 уникальных PID и новый PID оболочки. Прогон выполняется в GitHub Actions с публикацией **полного исходного кода**, ISO и логов.

## Границы

Это **новая реализация поведения части сборки 730**, а не побайтовое восстановление утраченных исходников. PID на этом этапе принадлежат реестру сеансов, **не являются аппаратно изолированными пользовательскими процессами**. Нет `.tea`-лоадера, установщика 730, независимых адресных пространств и двухтомного фонового копирования 20 МиБ. Только успешная проверка QEMU подтвердит гостевую работу F5.

Не заменять оригинальные ISO 730 и 744; `main` не изменять.
