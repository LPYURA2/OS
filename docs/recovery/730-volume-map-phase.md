# Восстановление 730 — этап Disk-1 (карта томов)

Источник: реальная исходная 709. Ветка: restore/styleos-709-to-730-canonical.
Предыдущий эталон: F5, независимые Notes и редактор, восстановление оболочки F10.

## Реализовано
- Новый freestanding слой desktop_volume_io: ограниченная адресация логического StyleFS-тома на физическом блочном устройстве с явным start LBA, длиной и отдельными I/O callbacks.
- Проверка доступной ёмкости без unsigned overflow; отказ при неподходящей длине, отсутствующих callbacks и при обращении вне логического тома.
- Режим только для чтения отключает запись и flush у StyleFS; неизвестные/неотформатированные носители не модифицируются и не форматируются автоматически.
- Существующий Проводник и StyleFS монтируют свой прежний диск через карту base=0, то есть рабочий профиль F5 намеренно не меняет ни диска, ни формата, ни пользовательских файлов.
- Host ASAN+UBSAN тест открывает и форматирует **только собственные временные RAM-диски**, монтирует два независимых StyleFS v2 с ненулевым смещением и защитой guard-секторов, проверяет создание/открытие раздельных файлов и режим только чтения.
- В CI добавлен обязательный отдельный test_desktop_volume_io.py. Ошибка теста ломает CI, все исходники архивируются.

## Что это ещё НЕ значит
- Гостевой Explorer пока реально монтирует **один** прежний диск; второй том только проверен на хосте. В интерфейсе новых дисков не объявлять.
- Ещё нет графического установщика 730, карты разделов реального Primary IDE boot-диска, отдельного смонтированного Data-1/Data-2, фонового копирования 20 МиБ или отмены.
- Ещё нет отдельного процесса для каждого native .tea приложения. Оригинальная бинарная 730 служит поведенческим эталоном, не исходником.
- Не выполнялось тестирование VirtualBox или железа.

Следующий шаг: явно описать геометрию установленного системного диска и безопасно реализовать обнаружение двух реальных хранилищ с проверкой signature и read-only установочного ISO, затем оба настоящих тома и копирование по шагам.
