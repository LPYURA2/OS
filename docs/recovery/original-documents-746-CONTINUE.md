# Продолжение StyleOS

В каждом ответе по StyleOS оставляй короткий блок «Актуальное состояние
и с чего начать в новом чате». Указывай реальную ветку, сборку, проверки,
ограничения и следующий рабочий шаг.

Пользователь проверяет не после каждой вкладки. Договорённость:
1. Закончить «Документы» по утверждённому альбому → одна внешняя приёмка.
2. «Презентации» и «Таблицы» как .tea → совместная приёмка.
3. Системные окна → приёмка.
4. Deep Drop и Проводник → приёмка.

Выданный промежуточный ZIP — 744 (b0da7ad, есть ISO, чистый VDI данных
и START.txt). PDF и команды работы с листом в этом архиве отсутствуют.
Последний внутренний этап — 746, ветка
`feature/styleos-documents-page-controls`, база `6b25a02`.
Отчёты: [744](test-results/documents-stable-pagination/README.md) — общая
разбивка, [745](test-results/documents-pdf/README.md) — PDF из тех же
листов, [746](test-results/documents-page-controls/README.md) — ручные
разрывы, колонтитулы, нумерация. QEMU не означает приёмку VirtualBox.
main не менялся.
[Состав первой полноценной версии](PROJECT.md#встроенные-приложения-первой-полноценной-версии)
зафиксирован отдельно.

В новом чате открыть ветку 746 и этот файл. Работать по
StyleOS-Documents-Full-Concept.pdf из утверждённого альбома
StyleOS-Approved-Mockups.zip. Следом закрыть «Проверку» и «Автоматизацию»
по альбому и сверить оставшиеся команды с макетами. Не считать наличие
вкладки реализацией. Одна общая приёмка «Документов» после завершения,
затем «Презентации» и «Таблицы».
StyleOS-Explorer-Mockups.pdf понадобится на этапе Проводника.

Рабочий стол не переделывать. Стандартная тема и «Тёплый графит»
сохраняются. Поведение — знакомые сценарии Windows 10, вид — StyleOS.
Показывать реальные файлы и тома. Приложения .tea не привязывать к
коду рабочего стола. Deep Drop — перенос между приложениями, кнопка
его уведомления перезапускает только перенос. «Восстановление» —
отдельная системная функция.
