# Матрёшка: Разрыв ОС — Termux v0.3.2 / T1A

**12 ноября 2026. Экспериментальная ОС для виртуального процессора M32 на Python.**

## Что теперь действительно работает

- Python эмулирует CPU, RAM, ROM, блочные диски, клавиатуру, консоль и таймер.
- Гостевая ROM-прошивка на собственном ассемблере читает ядро из `images/system.img` и сверяет контрольную сумму.
- **Новое T1A:** гостевое ядро читает каталог приложений с системного диска, самостоятельно копирует исполняемые сектора в выделенные слоты RAM, сверяет контрольную сумму и создаёт процессы.
- **Новое T1A:** гостевая shell команда `run 0`–`run 4` вызывает syscall `TRAP 10` для запуска нового приложения во время работы ОС. Эти программы НЕ загружаются Python из `.asm` при запуске.
- Ядро проверяет занятость слота до копирования нового исполняемого кода, чтобы не перезаписывать активную программу.
- Сохраняются старые команды `help`, `ps`, `info`, `clear`, `save`, `load`, `ls`, `rm`, `exit`, персистентный пользовательский диск и отдельная M8-ветка.

Это **не полноценная ОС**. Нет настоящей файловой системы, именованных файлов-исполняемых пакетов, GUI, компилятора внутри ОС, APK/EXE/.tea совместимости или утверждённой архитектуры для Proteus.

## Быстрый запуск в Termux

1. Скачай `MATRYOSHKA_Termux_v0.3.2.zip` в папку «Загрузки».
2. Открой Termux и выполни:

```sh
pkg install python unzip -y
termux-setup-storage
mkdir -p ~/matryoshka032
unzip -o ~/storage/downloads/MATRYOSHKA_Termux_v0.3.2.zip -d ~/matryoshka032
cd ~/matryoshka032
python matryoshka.py --selftest
python -m unittest discover -s tests -v
python tools/export_images.py --check
python matryoshka.py --os
```

В гостевой оболочке:

```text
help
run 0
run 1
ps
save Привет, Матрёшка!
load
exit
```

| Команда | Приложение из системного диска |
|---|---|
| `run 0` | `hello` — вывод текста |
| `run 1` | `counter` — счётчик |
| `run 2` | `taskmgr` — учебный просмотр процессов |
| `run 3` | `diskdemo` — пишет в сектор 3 *пользовательского* диска |
| `run 4` | `selfmod` — учебная модификация собственных инструкций |

Для выхода из ОС: `exit`. **Не вводи эти команды в Termux напрямую** — только после появления приглашения `M:>`.

### Безопасность данных / обновление

- v0.3.2 использует **отдельную** папку `~/matryoshka032`; ничего в v0.3.1 автоматически не заменяется.
- `images/system.img` — **только чтение**, 64 КиБ. `matryoshka_user_disk.img` — пользовательский диск, 64 КиБ, появляется рядом с `matryoshka.py` и НЕ включён в ZIP.
- Если нужна старая заметка из v0.3.1, после выхода из обеих ОС сначала сохрани резервную копию старого диска. Затем только при отсутствии нового файла допускается:

```sh
cp -n ~/matryoshka031/matryoshka_user_disk.img ~/matryoshka032/
```

Не копируй `matryoshka_user_disk.img` поверх `images/system.img`. Не делай `rm -rf` для старых сборок.

### Как менять программу самому

Открой `programs/hello.asm` в nano. Измени строку `.ascii`, но оставь метки `message` и `message_end`.

```sh
nano programs/hello.asm
python tools/export_images.py
python matryoshka.py --os
```

В ОС введи `run 0` — увидишь изменённое сообщение. Для восстановления исходника сравни с архивом v0.3.2; бинарники и системный образ пересобираются только явной командой экспорта.

Более подробный урок: `docs/T1A_LESSON_RU.md`.

## Как подтвердить, что приложение действительно загружено гостевым CPU

- В `boot()` Python только переносит прошивку в ROM и устанавливает выбор стартовой программы — **не компилирует и не копирует** пользовательские приложения.
- Каталог программ занимает сектор 17, бинарники лежат начиная с сектора 18. Гостевой код пользуется `OUT 50`, `OUT 51`, `OUT 52`, `IN 53` для чтения сектора.
- После чтения гость вычисляет аддитивную сумму 32-битных слов, сверяет её и выполняет привилегированную инструкцию `SPAWN`.
- Системный вызов `TRAP 10` позволяет оболочке выбрать новую программу. Перед чтением проверяется таблица занятости слотов в памяти ядра.

Ограничения: неизменные адреса слотов, максимум 8 PID на запуск (без переиспользования PID), 6 встроенных бинарников в каталоге включая shell, 32-битная сумма не криптографическая подпись, конкурентные записи в текстовый терминал иногда смешиваются. Не использовать VM как защитную песочницу для чужого кода.

## Проверки

```sh
python matryoshka.py --selftest
python -m unittest discover -s tests -v
python tools/export_images.py --check
python hardware_m8/m8.py --selftest
python hardware_m8/gate_alu.py
```

Тесты выполняют гостевые бинарники, проверяют отказ на повреждённых образах, запуск программы по syscall, отсутствие предзагрузки приложений Python, сохранение заметки между reboot и запрет перезаписи активного слота.

**Важно:** тесты выполнены в доступной Linux-среде. На твоём конкретном Android новая версия ещё не проверялась. Процессор M8 остаётся несовместим с M32; перенос в Proteus не начинался.

### Два `shell.bin` — почему?

`images/shell.bin` оставлен для совместимости с прежней диагностической сборкой и собран для старого базового адреса `0x8000`. **Он не используется при загрузке v0.3.2.** Действующая оболочка — `images/apps/shell.bin`, собранная для своего каталожного слота `0x17000` и упакованная в `images/system.img`.
