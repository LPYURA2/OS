# StyleOS SDK 0.1 Preview

Первый хостовый комплект для **x86‑64 StyleOS**. В комплекте пример
«Презентации» и шаблон собственного приложения. Windows-пакет содержит
уже собранный `artifacts/presentations.tea`. Он не требует сборки из исходников
для проверки содержимого.

**Граница Preview.** Мы собираем настоящий ELF x86‑64 и проверяем упаковку.
StyleOS не имеет загрузчика этого формата и пока не запускает пакет в
VirtualBox. У .tea здесь нет подписи издателя, графического API, системной
установки и стабильного ABI. На хосте проверена логика текстового слайда,
не работа приложения в гостевой ОС.

## Windows x64

1. Запустите `StyleOS-SDK-Setup-x64.exe`. По умолчанию SDK ставится в профиль
   пользователя. Системный PATH и права администратора не нужны.
2. В «Пуск → StyleOS SDK Preview» откройте **Read me**. Готовый пакет
   «Презентации» лежит в `artifacts\presentations.tea` внутри папки SDK.
3. **New project** создаёт вашу папку в `%USERPROFILE%\StyleOSProjects`.
   Введите имя и ID, например `example.my-app`.
4. В своем `main.c` измените строку `message`. **Build project** попросит
   путь к папке и создаст `build\application.tea` внутри неё. Пример можно
   пересобрать кнопкой **Build presentations**.
5. Для проверки пакета из командной строки используйте
   `StyleOS-SDK.cmd verify artifacts\presentations.tea`.

Компилятор и Python в комплекте локальные. Для установки и сборки интернет не
нужен. Состояние проверки Windows см. в отчёте этого этапа.

## Свой проект из терминала

Нужны Python 3.10+, Clang и LLD. Можно передать пути через `--clang` и `--lld`
или переменные `CLANG` и `LD_LLD`. Пример для команд из корня исходного репозитория.

```sh
python3 sdk/styleos_sdk.py new ../my-app --id example.my-app --name "My first app"
# Напишите свой текст в message в ../my-app/main.c.
python3 sdk/styleos_sdk.py build ../my-app --output ../my-app/build/my-app.tea
python3 sdk/styleos_sdk.py verify ../my-app/build/my-app.tea
```

В каталоге проекта два важных файла.

- `app.json` содержит имя, идентификатор и версию. Пример ID — `example.my-app`, версии — `0.1.0`.
- `main.c` содержит `styleos_app_text_v0`. Это текстовая функция, не обычный
  `main()`. Ваша программа получает байты, пишет результат в отдельный
  буфер и возвращает число записанных байтов. Функция не открывает окно и
  не работает напрямую с файлами или устройствами. У шаблона уже есть
  этот контракт, для первого опыта достаточно поменять `message`.

Пример «Презентации» принимает ограниченный текст слайда и возвращает его
как замену содержимого. Другие функции редактора и интерфейс не входят в
этот выпуск SDK. Для сборки отдельно от дерева ядра можно скопировать
`sdk/examples/presentations` в пользовательскую папку и передать её
команде `build`. В стандартных примерах нет зависимостей от исходников ядра.

## Что внутри .tea

Экспериментальный ZIP без сжатия с двумя именованными файлами.
`manifest.json` описывает приложение, x86‑64, экспериментальный интерфейс,
длину, контрольную сумму SHA-256 и точку входа ELF. `payload.elf` содержит
отдельно скомпилированный код. `verify` не извлекает и не запускает пакет.
Проверяются формат, известная архитектура, размеры и целостность. Это не
защита от недоверенного издателя и не утверждённый формат выпуска StyleOS.

Проверки

```sh
python3 -m unittest discover -s sdk/tests -v
```

Темы, виджеты, графические окна и конструктор приложений — после первого
рабочего контракта с оболочкой StyleOS. При появлении поддержки
AArch64 те же исходники можно будет собрать в отдельный целевой бинарник.
